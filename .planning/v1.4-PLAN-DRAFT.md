## Ordering & dependencies

```
Phase 23 (close v1.3) ─┬─▶ Phase 24 (fetch foundation) ─┬─▶ Phase 25 (quality dedup)
                       │                                └─▶ Phase 26 (app-shell dedup)
                       └─▶ Phase 29 (UX backlog) ◀───────────── independent
                                                       
Phase 27 (efficiency)   can start any time after 24
Phase 28 (micro-sweep)  can start any time; ideally after 25+26 to absorb disables
```

- **23 must ship first** — W1-W3 are correctness bugs.
- **24 unblocks 25 + 26** — `useAsyncRun` + `Map<serverUrl>` caches are prerequisites for the hook dedup.
- **27 + 28** are parallel-safe with 25/26.
- **29 is independent** of the refactor thread — ship when convenient.

## Risk callouts

- **R14 (context split):** `QualityMetricsContext` is consumed by every panel.
  Splitting it touches ~20 files and risks silent re-render regressions.
  Schedule with care — possibly defer to v1.5.
- **R15 (lazy routes):** verify tests still find lazy-loaded components
  (`render()` needs to await Suspense).
- **Phase 23 UAT:** 8 human UAT items need a running Blaze server. Not all
  Claude-automatable.
- **External validator (T1):** scope creep risk — keep to "configure URL,
  probe connectivity, surface active strategy" for v1.4; do NOT implement a
  local full-validator.

## Out of scope for v1.4

- New FHIR resource-type features (no Practitioner / Medication deep-dives)
- SMART-on-FHIR / OAuth flows (project scope explicitly excludes)
- Server-side bulk export ($export)
- Patient-chart narrative views
- Any Mantine 9 / React 19 migration
