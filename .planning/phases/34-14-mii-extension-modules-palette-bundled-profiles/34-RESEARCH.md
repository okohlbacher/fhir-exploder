## Summary

Phase 34 is a **data-payload phase on top of a pre-built shell**: Phase 33 shipped the widened schema (`string | string[]`, `category`, `patientSearchParamOverrides`, `extraQueryByType`), the four helpers (`fhirResourceTypesOf`, `findModuleForType`, `getPatientSearchParamForType`, `getExtraQueryForType`), the `Promise.all` fan-out, the base/extension Tabs partition with selective `keepMounted`, the Dashboard Drawer click target, and the D-17 per-module `patientSearchParam` contract test — all verified green. Phase 34 lands (1) 14 append-only extension rows in `MII_MODULES`; (2) 7 `MantineColorsTuple`s in `src/theme.ts` leaving the base 7 untouched; (3) 21 Tabler icon assignments rendered in Timeline dots + tab labels + Dashboard tile swatches; (4) 14 trimmed `StructureDefinition` JSON files under `src/quality/profiles/extensions/` generated by a new `scripts/fetch-mii-profiles.mjs` wrapping `fhir-package-loader@^2.2.4` on a `prepare` npm lifecycle hook with warn-and-continue failure semantics; (5) CC-BY-4.0 attribution in an appendix to LICENSE + per-package metadata in `ATTRIBUTION.md`; (6) the empty-state dimming UX (`opacity: 0.55` when `resources.length === 0`) plus a `patients.hideEmptyExtensions.v1` localStorage toggle.

The phase has **no runtime dependency additions** — `fhir-package-loader@^2.2.4` is a devDep only; the browser bundle grows by committed JSON + 14 icon imports + 70 hex strings (budget < 100 KB post-gzip per D-23). The dominant risk is not correctness (Phase 33's D-17 contract catches that) but: pre-GA package version drift (Kardiologie alpha, Symptom ballot), CC-BY-4.0 attribution completeness, WCAG AA contrast at `primaryShade: 6` against both `#ffffff` card backgrounds and `#e7ecff` active-pill backgrounds, and the `|| true` escape on the `prepare` hook being robust enough that `npm install` on an offline machine still succeeds.

**Primary recommendation:** Execute the 6-plan split in `34-CONTEXT.md` D-25 verbatim — audit doc first (34-01), theme + schema-field addition (34-02), fetch script + committed JSON + license (34-03), 14 data rows + icons (34-04), empty-state UX (34-05), UAT artifacts (34-06). Each plan ends green on `npm test` (≥ 902 target) + `npx tsc -b --noEmit`. The ROADMAP-locked palette family names (`oncology`, `imaging`, `genetics`, `pathology`, `bioanalysis`, `administration`, `patient-reported`) are not renameable; assignment of the 14 modules across these 7 palettes follows the D-05 clinical-semantic grouping with WCAG-driven pair swapping within a family permitted but not cross-family rename.

```typescript
export interface MiiModule {
  // ... existing fields unchanged ...
  /**
   * Tabler icon component name (from '@tabler/icons-react').
   * Rendered at three sites per D-07: Timeline dot (16-px), tab
   * subtitle (14-px), Dashboard tile swatch (32-px), Drawer header.

}
```

**Why string and not component reference:** storing the icon as a string key keeps `MiiModule` JSON-serializable (no React components in the data type) and side-steps SSR/ESM import-cycle concerns. Consumers render via a local lookup map:

```typescript
// In each consumer (MiiModuleTabs, ClinicalTimeline, DashboardPage):
import {
  IconUser, IconBedFlat, IconStethoscope, IconMedicalCross, IconFileSignature,
  IconFlask, IconPill, IconRadioactive, IconHeart, /* ... 14 extension icons */
} from '@tabler/icons-react';

const ICON_MAP = {
  IconUser, IconBedFlat, IconStethoscope, IconMedicalCross, IconFileSignature,
  IconFlask, IconPill, IconRadioactive, IconHeart, /* etc. */
} as const;

const IconComponent = module.icon ? ICON_MAP[module.icon] : null;
```

Rejected because (a) `MII_MODULES` serializes cleanly as JSON today and that's useful for debugging/test fixtures; (b) it forces every consumer to eagerly import 21 icons even when rendering only 1 — Tabler's per-icon tree-shaking works best with explicit named imports.   ['de.medizininformatikinitiative.kerndatensatz.dokument',      '2026.0.1'],
```javascript
  ['de.medizininformatikinitiative.kerndatensatz.mtb',           '2026.0.1'],
  ['de.medizininformatikinitiative.kerndatensatz.pros',          '2026.2.0'],
];

const PRE_GA_PATTERN = /-(alpha|beta|rc|ballot|draft)/i;

function trim(sd) {
  // Match src/quality/profiles/*.json shape: preserve only fields the
  // completeness walker reads. Strip comments, metadata, bindings that
  // aren't 'required', etc.
  return {
    resourceType: 'StructureDefinition',
    url: sd.url,
    name: sd.name,
    type: sd.type,
    snapshot: {
      element: (sd.snapshot?.element ?? []).map((e) => {
        const out = { path: e.path };
        if (e.min !== undefined) out.min = e.min;
        if (e.max !== undefined) out.max = e.max;
        if (e.mustSupport !== undefined) out.mustSupport = e.mustSupport;
        if (e.sliceName !== undefined) out.sliceName = e.sliceName;
        if (e.type !== undefined) out.type = e.type;  // preserved by base profiles
        if (e.binding?.strength === 'required') out.binding = e.binding;  // preserved
        return out;
      }),
    },
  };
}

async function main() {
  await fs.mkdir(OUT_DIR, { recursive: true });
  const log = (level, msg) => console[level === 'error' ? 'warn' : 'log'](`[${level}] ${msg}`);
  const loader = await defaultPackageLoader({ log });

  for (const [name, version] of EXTENSION_PACKAGES) {
    if (PRE_GA_PATTERN.test(version)) {
      console.info(`[info] bundling pre-GA version: ${name}@${version}`);
    }
    const status = await loader.loadPackage(name, version).catch((err) => {
      console.warn(`[warn] ${name}@${version} — fetch failed: ${err.message}`);
      return LoadStatus.FAILED;
    });
    if (status !== LoadStatus.LOADED) {
      console.warn(`[warn] ${name}@${version} — status ${status}; skipping, relying on committed JSON`);
      continue;
    }
    const sds = loader.findResourceJSONs('', {
      resourceTypes: ['StructureDefinition'],
      packageId: name,
    });
    for (const sd of sds) {
      // Filename convention: `<type>-<slug-of-sd.name>.json` — mirrors
      // base profiles naming (e.g., `Patient-person.json`).
      const slug = (sd.name ?? sd.id ?? sd.url.split('/').pop() ?? 'unknown')
        .toLowerCase()
        .replace(/[^a-z0-9]+/g, '-')
        .replace(/^-+|-+$/g, '');
      const filename = `${sd.type}-${slug}.json`;
      await fs.writeFile(
        path.join(OUT_DIR, filename),
        JSON.stringify(trim(sd), null, 2) + '\n',
      );
    }
    console.log(`[ok] ${name}@${version} — wrote ${sds.length} StructureDefinition(s)`);
  }
}

main().catch((err) => {
  // Last-ditch safety — any unexpected throw must NOT fail `npm install`.
  // D-14: prepare hook appends `|| true` anyway, but belt-and-braces.
  console.warn(`[warn] fetch-mii-profiles failed globally: ${err.message}`);
  process.exit(0);
});
```

**`src/quality/profiles/extensions/index.ts` (generated + hand-maintained):**

Since the fetch script emits one JSON per `StructureDefinition` and each filename is unique (`type-slug.json`), the extensions index should iterate filenames programmatically. **But** Vite's static-import requirement means dynamic-string imports don't tree-shake well. Recommended pattern:

```typescript
// src/quality/profiles/extensions/index.ts
// Regenerated by scripts/fetch-mii-profiles.mjs at the end of its run —
// writes this file with an explicit static import per .json sibling.
// linguist-generated=true applies to this file too.
import type { StructureDefinition } from '@medplum/fhirtypes';
import sd1 from './Condition-mii-pr-onko-diagnose.json';
import sd2 from './Observation-mii-pr-onko-tumor-size.json';
// ... N imports, N = total fetched StructureDefinitions

export const REGISTRY: Record<string, StructureDefinition> = {
  [(sd1 as unknown as StructureDefinition).url]: sd1 as unknown as StructureDefinition,
  [(sd2 as unknown as StructureDefinition).url]: sd2 as unknown as StructureDefinition,
  // ...
};
```

The fetch script writes this `index.ts` alongside the JSONs as part of its final pass. An alternative is `import.meta.glob` (Vite-native) but that only works at Vite build time — not in `npm test` (Vitest uses Vite too but node_modules resolution differs) and not in plain Node scripts. Static explicit imports are the safest cross-tool pattern.

## Pitfalls

### P-01: Pre-GA package version drift (HIGH likelihood)

**Symptom:** `fhir-package-loader` fails with `LoadStatus.FAILED` after Kardiologie promotes `2026.0.0-alpha.2` → `2026.0.0` (GA) and the prior alpha version is unpublished from packages.fhir.org.

**Root cause:** Pre-GA versions are mutable; `EXTENSION_PACKAGES` pins exact semver. When the alpha is unpublished, the pin breaks.

**Prevention:**
- For pre-GA packages (`PRE_GA_PATTERN` match in the script), fall back to a "latest" resolution: `loader.loadPackage(name, 'latest')` if the exact pin fails.
- Alternately: document in `ATTRIBUTION.md` + `STATE.md` that pre-GA pins must be reviewed at each milestone.
- D-13 warn-and-continue already covers the acute failure — the committed JSON remains valid until someone reruns `fetch:profiles`.

**Warning signs:** `console.warn` spam during `npm install` on fresh clones; `prepare` hook logs `status FAILED` for Kardiologie/Symptom.

### P-02: `subject=` vs `patient=` mismatch per module (same class as UAT-FU-06)

**Symptom:** An extension tab (e.g., Biobank → Specimen) is empty even though the server has Specimen data for the patient.

**Root cause:** R4 Specimen has no `patient` search param; it has `subject`. Using the module default `patient` silently yields zero results. Same class of bug as UAT-FU-06 for Synthea/base-7 (resolved by 33-01-INVESTIGATION).

**Prevention:**
- Phase 33 D-17 contract test is the structural gate. Plan 34-01 audit doc MUST probe each `(module, type)` pair against live Blaze and populate `patientSearchParamOverrides` for any that require `subject=` or other non-`patient` params.
- Known exceptions (re-verify in 34-01 live probe):
  - **Specimen** → `subject=` (R4 has no `patient` param on Specimen)
  - **ResearchStudy** → no per-patient search param directly; use `enrollment=Patient/{id}` or chained through ResearchSubject
  - **ImagingStudy** → R4 has both `patient` and `subject`; servers may index differently
  - **DocumentReference** → both exist; standard is `patient`
- D-17 test row per `(module, type)` pair is the contract. Missing row → coverage assertion fails.

**Warning signs:** An extension tab with `opacity: 0.55` on a patient who you *know* has data of that type.

### P-03: `prepare` hook runs on CI / fresh clones without network (MEDIUM)

**Symptom:** `npm install` fails on a CI runner with a restrictive egress policy; developer clones the repo behind a corporate firewall and install hangs.

**Root cause:** `prepare` runs automatically on `npm install` for any dependency, including production installs. If `fhir-package-loader` tries to reach `packages.fhir.org` and the network is blocked, the script hangs until `fhir-package-loader`'s internal timeout or fails.

**Prevention:**
- D-14 `|| true` escape ensures non-zero exit never propagates.
- Ensure the script has a wall-clock timeout — wrap each `loader.loadPackage()` call in a `Promise.race` against a 30-second timer. `fhir-package-loader` may have its own retry logic that extends the wall-clock beyond reasonable limits.
- Document in README: `npm install --ignore-scripts` as an escape hatch for offline installs.

**Warning signs:** `npm install` taking > 5 minutes; CI logs show repeated HTTPS connection attempts to `packages.fhir.org`.

### P-04: WCAG AA failure at `primaryShade: 6` (HIGH likelihood)

**Symptom:** The badge color at shade 6 fails contrast check against white text on the card background.

**Root cause:** Mantine's Colors Generator produces evenly-spaced shades, but "shade 6" contrast depends on the seed hue's luminance. Yellow/orange/lime seeds tend to fail 4.5:1 at shade 6 against white text.

**Prevention:**
- D-06 WCAG audit is the gate. If a palette fails at shade 6, either (a) regenerate with a slightly darker seed, (b) use shade 7 for that family's `badgeColor` rendering, (c) override text color to `theme.gray[9]` on shade 6 (dark-on-light instead of light-on-dark).
- Known risky families: `bioanalysis` (teal seeds can be too light), `imaging` (cyan). Safer families: `oncology` (red), `pathology` (violet), `administration` (indigo, matches Mantine default).
- Contrast measurement tool: `npx wcag-contrast <fg> <bg>` — one-off design tool, NOT a runtime dep (rejected per STACK.md).

**Warning signs:** The audit doc table shows 3.8:1 or similar values in the "text on shade-6" column.

### P-05: 7-palette collision when 14 modules map to 7 colors

**Symptom:** Onkologie and MTB both show the same badge color — users can't tell them apart on a timeline mixing both.

**Root cause:** D-05 maps 14 modules to 7 palettes (2 modules per color). Color alone is ambiguous.

**Prevention:**
- D-07 icon-on-every-render is the structural mitigation. Each of the 21 modules has a unique icon; adjacent pairs sharing a color are distinguishable by icon.
- Deuteranopia test (D-09) verifies this holds under color blindness — the 7-color palette collapses further under deuteranopia but icons remain.
- Ordering (D-01 alphabetical) ensures co-colored pairs aren't adjacent (Onkologie at 'O' vs. MTB at 'M' — 3 positions apart — visually separated in the tab row).

**Warning signs:** Timeline with simultaneous Onkologie + MTB entries where the user cannot tell them apart by the badge.

### P-06: Deuteranopia perceptual collapse

**Symptom:** Under deuteranopia (red-green color blindness), `oncology` (red) and `pathology` (violet) look identical; `imaging` (cyan) and `bioanalysis` (teal) collapse.

**Root cause:** Deuteranopia compresses red-green discrimination; palettes that differ only in R-G channels become indistinguishable.

**Prevention:**
- D-09 screenshots under Chrome DevTools deuteranopia emulation capture the state.
- Icons are the primary discriminator — color is secondary.
- If the audit reveals >2 pairs collapse, consider shifting seeds toward blue-yellow axis where possible. But "rainbow palette" is an anti-feature (FEATURES.md §4.d) — 7 families is already a design constraint.

**Warning signs:** Deuteranopia screenshot shows 3+ modules sharing visual identity.

### P-07: CC-BY-4.0 attribution incomplete (license compliance)

**Symptom:** Legal review flags the bundled profiles for insufficient attribution — CC-BY-4.0 requires (a) URL to license, (b) attribution per work, (c) notice of modifications.

**Root cause:** `ATTRIBUTION.md` is generated from package metadata; if a package lacks author info in `package.json` inside the tarball, attribution is thin. Some MII IG repos don't populate `author` cleanly.

**Prevention:**
- `ATTRIBUTION.md` follows the D-15 template verbatim (canonical URL + version + license + source URL + fetched-on). The canonical URL serves as the attribution to the MII project — CC-BY-4.0 says attribution should follow "any reasonable manner" and URL-to-source is conventional.
- LICENSE appendix explicitly states: "Modifications from the original packages: trimmed to the subset of StructureDefinition fields used by the FHIR Exploder completeness walker." This satisfies CC-BY-4.0 §3.a.1.B (indication of modifications).
- Per `creativecommons.org/licenses/by/4.0/` — the minimal attribution is: (1) name of creator, (2) copyright notice, (3) license text or URL, (4) notice referring to the disclaimer of warranties, (5) URI or hyperlink to the material. [CITED: creativecommons.org/licenses/by/4.0/legalcode]

**Warning signs:** A packaging audit (pre-release) finds missing modification notices or upstream URL mismatches.

### P-08: Bundle-size blowup from un-trimmed profiles

**Symptom:** `npm run build` ships +300 KB to the browser bundle.

**Root cause:** Full MII StructureDefinitions include extension slicings, bindings, examples, narrative — ~150 KB per profile. Committed un-trimmed would blow the D-23 budget (100 KB post-gzip).

**Prevention:**
- Trim algorithm (shown in fetch script) preserves ONLY the fields the completeness walker reads. Budget estimate: 14 packages × 5-20 profiles × ~150 B/element = 20-80 KB raw; <40 KB post-gzip.
- Treemap before/after (D-23) quantifies exactly. If above budget, tighten the trim by dropping `binding.strength !== 'required'` entries (already in the script), dropping `type[]` (saves a lot for choice types), or switching storage to one merged JSON per package.

**Warning signs:** Visualizer treemap shows `src/quality/profiles/extensions/` occupying >10% of the bundle.

### P-09: `fhir-package-loader` v2 API surface mismatch with hand-written code

**Symptom:** `scripts/fetch-mii-profiles.mjs` throws `TypeError: loader.loadPackage is not a function` during `prepare`.

**Root cause:** The v2 release is "totally different from v1" [CITED: github.com/FHIR/fhir-package-loader]. The STACK.md research referenced `loadDependencies` which is v1 terminology. The v2 API exports `defaultPackageLoader()` which returns a `PackageLoader` with `loadPackage(name, version)` + `findResourceJSONs(key, options)`.

**Prevention:**
- Use the verified v2 API from the GitHub README (see Implementation Approach §34-03 code). NOT the v1 `loadDependencies(['pkg@ver'])` shape.
- Integration test: `scripts/fetch-mii-profiles.test.mjs` mocks `fhir-package-loader` with `vi.mock('fhir-package-loader', () => ({ defaultPackageLoader: vi.fn(...), LoadStatus: { LOADED: 0, NOT_LOADED: 1, FAILED: 2 } }))` and asserts the script writes the expected filenames with the trim shape.

**Warning signs:** `npm install` fails on first run with a stack trace pointing at `scripts/fetch-mii-profiles.mjs`; `fhir-package-loader@^3.x.x` release notes mention further breaking changes.

**Symptom:** v1.6 ships with `hideEmptyExtensions` extended to per-module granularity; existing `Record<patientId, boolean>` users lose their preference silently.

## Unknowns

### U-01: Exact current versions of the 14 MII packages on 2026-04-24

**What we know:** STACK.md (committed 2026-04-23) lists versions that are one day old; most are stable (`2026.0.X`); two are pre-GA (Kardiologie `2026.0.0-alpha.2`, Symptom `2024.0.0-ballot`).

**What's unclear:** Whether any package shipped a new minor/patch between 2026-04-23 and 2026-04-24.

**Decision default:** Plan 34-01 re-probes `packages.fhir.org` for each package and commits the verified versions to `color-design-audit.md`. If a version has bumped, update `EXTENSION_PACKAGES` in the fetch script (34-03) accordingly.

### U-02: Which extension IGs declare their own `SearchParameter` resources

**What we know:** MII extension IGs *may* declare their own SearchParameters, overriding base R4. Most do not — they inherit.

**What's unclear:** For each of the 14 packages, whether any declare a `SearchParameter` that changes the patient-scoping semantics. (Example: Bildgebung might declare `Patient-imagingstudy-patient` replacing the base `patient` with `subject`.)

**Decision default:** 34-01 audit probes live Blaze for each `(module, type)` pair — the empirical result (what actually returns data) dominates over IG-declared theory. If probe says `patient=` works, use `patient`; if `subject=` is the only one that returns, record as override.

### U-03: Total JSON count — how many StructureDefinitions across all 14 packages?

**What we know:** Onkologie alone ships ~60 profiles (STACK.md). Other packages ship 5-30. Rough total: 150-400 profiles.

**What's unclear:** Exact count; impact on bundle-size budget (D-23 = 100 KB post-gzip).

**Decision default:** Run `fetch:profiles` once locally, measure `du -sh src/quality/profiles/extensions/`, measure post-gzip via `tar c src/quality/profiles/extensions/ | gzip | wc -c`. If above 100 KB gzipped, tighten trim (drop `type[]` for non-primitive elements, drop `binding` for non-required strengths — these are low-signal for the completeness walker).

### U-04: Whether `fhir-package-loader` v2 has a wall-clock timeout

**What we know:** The v2 API uses `defaultPackageLoader()` + `loadPackage(name, version)` which internally uses an HTTPS client with configurable retry and timeout.

**What's unclear:** Default timeout value; whether a slow/unreachable `packages.fhir.org` can hang `npm install` for minutes.

**Decision default:** Wrap each `loader.loadPackage()` call in a `Promise.race` against a 30-second external timeout in `scripts/fetch-mii-profiles.mjs`. Document in P-03.

### U-05: MTB and PRO package naming on packages.fhir.org

**What we know:** STACK.md lists MTB as `de.medizininformatikinitiative.kerndatensatz.mtb@2026.0.1` and PRO as `de.medizininformatikinitiative.kerndatensatz.pros@2026.2.0` (note: `pros` with trailing 's' — likely typo-resistance on the publisher's part).

**What's unclear:** Whether PRO could alternately be published under `...pro` (singular) — some MII IGs have used both forms historically.

**Decision default:** 34-01 probes both names (`pros` and `pro`) against `packages.fhir.org` and records which resolves. Use the resolving name in `EXTENSION_PACKAGES`.

### U-06: `prepare` hook on `npm ci` (vs `npm install`)

**What we know:** `npm install` runs `prepare` by default. `npm ci` (CI-optimized install) also runs `prepare` unless `--ignore-scripts` is set.

**What's unclear:** Whether the project's existing CI pipeline uses `npm ci --ignore-scripts`.

**Decision default:** Assume `npm ci` runs `prepare` (most CI setups). Committed JSON is the safety net — if `prepare` fails/hangs on CI, the committed JSON ships regardless.

## Key Decisions (research-team-locked technical picks)

Not user-facing. These are implementation-level picks the planner inherits.

- **K-01: `MantineColorsTuple` key naming.** Use Mantine's convention: camelCase keys for tuples defined as TypeScript consts (`oncology`, `imaging`, `bioanalysis`), kebab-case string key for the one multi-word name (`'patient-reported'`). `createTheme({ colors: { oncology, imaging, ..., 'patient-reported': patientReported } })` works because Mantine accepts any string key.

- **K-02: Seed hexes NOT locked here.** Plan 34-01 audit doc picks the 7 seed hexes using the Mantine Colors Generator (interactive web tool). WCAG AA at shade 6 is the pass gate. Research suggests these seeds as starting points (adjustable):
  - `oncology`: `#e03131` (Mantine red-7, reddened)
  - `imaging`: `#0c8599` (Mantine cyan-7)
  - `genetics`: `#8e4ec6` (Mantine grape-7)
  - `pathology`: `#6741d9` (Mantine violet-7, darkened)
  - `bioanalysis`: `#099268` (Mantine teal-8 — shade 8 to clear contrast)
  - `administration`: `#364fc7` (Mantine indigo-8)
  - `patient-reported`: `#c2255c` (Mantine pink-7)
  These are PLACEHOLDERS — the audit produces the real hexes. [ASSUMED]

- **K-03: Icon reference as string, not component.** `MiiModule.icon?: string` (e.g., `'IconRadioactive'`), resolved via `ICON_MAP` in each consumer. JSON-serializable; no cyclic-import risks; preserves tree-shaking via explicit named imports in `ICON_MAP`.

- **K-04: Fetch script = `.mjs` ESM, Node 18+.** Matches `fhir-package-loader` engine requirement. Avoids `ts-node` at install time (cold start too slow for `prepare`).

- **K-05: Extension registry keyed by canonical URL, not resource type.** Each package has multiple profiles of the same type (Onkologie has 5+ Condition profiles). Keying by `sd.url` keeps them distinct. Base registry stays keyed by `type` (unchanged, no multi-profile-per-type conflicts in base 7).

- **K-06: Trim algorithm preserves `type`, `binding.strength === 'required'`, `sliceName`.** Base profiles preserve `type` (see `Patient-person.json:13` `"type": [{ "code": "Identifier" }]`) and required bindings (see `:28-30`). Extension trim follows the same rule for symmetry. Drops: `definition` text, `short` text, non-required bindings, `example[]`, `mapping[]`, `constraint[]` except those on the slicing discriminator.

- **K-07: `|| true` escape + committed JSON = belt-and-braces offline safety.** D-14 `\|\| true` prevents the `prepare` script exit code from failing `npm install`. Committed JSON (D-12) ensures `npm test` and `npm run build` work even if the script was never run (e.g., CI with `--ignore-scripts`, or offline first clone).

- **K-08: Empty-state UX = opacity wrapper on `MiiModuleTab` panel + empty-copy-in-body.** NOT a sibling "hide the tab pill entirely" approach — the tab pill stays visible (discoverability axiom, FEATURES.md). Only the PANEL body dims + the copy changes. Toggle in `MiiModuleTabs` hides *all* empty extension tab pills when active, persisted per patient.

- **K-09: Test for palette uses Vitest snapshot against `theme.colors` keys + shade count, NOT hex-value matching.** Hex values are audit-doc territory; locking them in a snapshot creates churn when the audit regenerates. Structural snapshot (keys exist + 10 shades each) is the invariant.

- **K-10: `scripts/fetch-mii-profiles.test.mjs` mocks `fhir-package-loader` at the module level.** Vitest's `vi.mock('fhir-package-loader', () => ({...}))` replaces the export surface. The test asserts: (a) trim shape on a synthetic SD input, (b) correct filename naming (`<type>-<slug>.json`), (c) pre-GA packages emit `console.info`, (d) fetch failure path still exits 0.
