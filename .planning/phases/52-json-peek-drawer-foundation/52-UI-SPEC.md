# Phase 52 — UI Design Contract

> Visual and interaction contract for the JSON Peek Drawer Foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase scope (visual surfaces):**
> 1. `JsonPeekDrawer` — 420px right-side overlay-less drawer, app-mounted at `AppLayout`
> 2. `JsonViewer` — extracted JSON renderer (wraps existing `JsonTreeView`), single source of truth
> 3. Focus affordance on `SearchResultsPage` table rows (`tabIndex=0` + visible focus ring)
> 4. `[Open full →]` button + drawer title (no new visual primitives — Mantine `Drawer` defaults)
>
> **Not in scope:** drawer toolbar (Copy/Download/validate chip → Phase 54), patient list / reference-chip wiring (Phase 53), 4-mode shell (Phase 54).

## Copywriting Contract

Every visible string in Phase 52 surfaces is locked here.

| Element | Copy | Source |
|---------|------|--------|
| Drawer title (left side) | `{resourceType}/{id}` rendered in `ff="monospace"` (e.g. `Patient/abc-123`) | CONTEXT specifics line 107 + D-14 |
| Drawer title (right side, primary CTA) | `Open full →` | CONTEXT D-16 + specifics line 108 (verbatim — including the trailing arrow `→` U+2192) |
| Drawer title fallback when resource missing | `JSON peek` | new (Mantine `Drawer` requires a non-empty title node) |
| Drawer close button (×) | (Mantine default `aria-label="Close"`) | Mantine `Drawer` `withCloseButton={true}` default — no override |
| Empty state — focused row but resource null | not reachable in Phase 52 (Explorer rows always carry their `Resource` object); contract: do nothing on `J` if `focusedResource == null` (no toast, no drawer) | CONTEXT D-12 implicit |
| Error state — drawer fails to render JSON | no error UI in Phase 52. `JsonTreeView` handles malformed values (renders `String(value)`); `Resource` shape guaranteed by Medplum types. | RESEARCH §Security — no XSS surface |
| Reference unresolvable (Phase 53 scope) | NOT defined here — Phase 53 / PEEK-04 owns this string | deferred |
| Keyboard hint (optional, not required this phase) | `Press J to peek · Esc to close · Enter to open full` (suggested for Explorer page footer; defer to Phase 55) | suggestion only |

**Primary CTA contract:** `Open full →` (verb + adjective; arrow disambiguates from in-drawer-open state). This label is binding — must match grep `git grep -rn "Open full" src/` to exactly one source location after implementation.

**Destructive actions in this phase:** none. The drawer is read-only; closing the drawer is non-destructive (`Esc`, ×, or `J` on another row all just dismiss/swap content).

**Toast contract:** Phase 52 emits **zero** toasts. PEEK-04 (Phase 53) extends this rule for failed reference resolution → inline state only, no toast.

## Interaction Contract

Phase 52 introduces three keyboard interactions and one mouse interaction. All bind to specific elements; all respect the input-focus guard.

### Keyboard — global / row-scoped

| Key | When | Action | Guard | Source |
|-----|------|--------|-------|--------|
| `J` | A `<Table.Tr>` in `SearchResultsPage` is `document.activeElement` (or contains it) AND `tag !== 'INPUT'/'TEXTAREA'/'SELECT'` | Open drawer with that row's resource; capture `originElement = document.activeElement` | input-focus guard (RESEARCH Pattern 3) | PEEK-01, CONTEXT D-04, D-05 |
| `J` | Drawer is already open and a different row is focused | Replace `peekState.resource`; drawer stays mounted (`opened=true`); update `originElement` | input-focus guard | PEEK-02, CONTEXT D-07 |
| `Esc` | Drawer is open | Close drawer; call `originElement.focus()` to return focus to originating row | Mantine `closeOnEscape={true}` default | PEEK-02, CONTEXT D-06 |
| `Enter` | Drawer is open AND `tag !== 'BUTTON'/'A'/'INPUT'/'TEXTAREA'/'SELECT'` (Pitfall 5 guard) | Navigate to `/explorer/{type}/{id}?mode=json`; close drawer | input + button + anchor guard | PEEK-03, CONTEXT D-10, RESEARCH Pitfall 5 |

### Mouse — drawer header

| Element | Action | Result |
|---------|--------|--------|
| `[Open full →]` button | click | Same as `Enter`-while-drawer-open: navigate to `?mode=json` and close drawer |
| `×` close button (Mantine default) | click | Same as `Esc`: close drawer + restore focus |
| Drawer title text (`{type}/{id}`) | none | Plain text — not interactive (not a link). `Open full →` is the affordance. |

### Focus management — drawer lifecycle

| Phase | Behavior | Implementation |
|-------|----------|----------------|
| Pre-open | User focuses `<Table.Tr>` via keyboard (`Tab`) or pointer | `tabIndex={0}` on each `Table.Tr`; visible focus ring per Color section |
| Open | `openPeek(resource, originElement)` stores `originElement` in context state | CONTEXT D-15 |
| Open (in-drawer) | `trapFocus={true}` keeps Tab cycling inside drawer (× → `[Open full →]` → JSON tree → ×) | CONTEXT D-09; Mantine built-in |
| Close | `returnFocus={false}` on Drawer; manual `originElement?.focus()` after Mantine animation completes | RESEARCH §Anti-patterns + Pattern 6 |
| Content swap (open → different row) | Drawer stays mounted; `peekState` updates; no animation; `originElement` updates to new row | CONTEXT D-07 |

### Visual contract — drawer config (locked)

| Mantine prop | Value | Reason |
|--------------|-------|--------|
| `position` | `"right"` | PEEK-01 |
| `size` | `420` (number → 420px) | PEEK-01, RESEARCH Pitfall 1 |
| `trapFocus` | `true` | CONTEXT D-09 (a11y safe) |
| `withOverlay` | `false` | CONTEXT D-09 (lightweight visual; user can see table behind) |
| `returnFocus` | `false` | RESEARCH anti-pattern — manual focus return required |
| `closeOnEscape` | `true` (default) | PEEK-02 |
| `closeOnClickOutside` | `true` (default; harmless with `withOverlay={false}` since there's no backdrop to click) | Mantine default |
| `withCloseButton` | `true` (default) | shows × in title bar |
| `keepMounted` | `false` (default) | drawer unmounts on close; state resets cleanly |
| `padding` | `"md"` (16px) | matches `DashboardPage` reference |

### Animation

| Surface | Animation | Spec |
|---------|-----------|------|
| Drawer open | Slide in from right | Mantine default (~150ms ease-out) — not overridden |
| Drawer close | Slide out to right | Mantine default — not overridden |
| Content swap (J on different row) | **None** — instant content replacement | required by PEEK-02 ("swaps drawer content without unmounting"); RESEARCH Anti-patterns |
| Focus ring on row | None (instant) | browser default outline |

## Visual Acceptance Criteria

For Phase 52 to pass `gsd-ui-checker`:

1. **Drawer dimensions** — open drawer; DevTools confirms `--drawer-size: 420px` (Mantine numeric→px conversion)
2. **No overlay** — drawer is open; underlying Explorer table is fully visible behind drawer (no dimming, no backdrop)
3. **Focus ring visible** — `Tab` to a row in `/explorer/Patient`; row shows 2px indigo `--accent-ring` outline
4. **Mono title** — drawer title left side renders in IBM Plex Mono (not IBM Plex Sans)
5. **Open full → label exact** — `git grep -rn "Open full →" src/` returns the `JsonPeekDrawer.tsx` source
6. **JSON tree color contract preserved** — open drawer, see `red.7` keys, `green.8` strings, `blue` numbers, `violet` booleans (unchanged from `JsonTreeView`)
7. **No new toast** — close + reopen + content-swap drawer sequence emits zero `notifications.show(...)` calls
8. **Focus return** — open drawer with `J`, press `Esc`, originating `<tr>` has focus (visible ring re-appears)
9. **Content swap, no flicker** — drawer open with row A's resource; `J` on row B (focused via `Tab`); drawer remains open, content updates instantly, no slide-out/in
10. **App-wide mount** — open drawer from `/explorer/Patient`, do not close, navigate to `/explorer/Observation`; drawer stays mounted (PeekProvider survives route change)
