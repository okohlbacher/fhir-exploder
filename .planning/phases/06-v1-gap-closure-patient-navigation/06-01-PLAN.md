<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL bar → React Router `useParams` | `patientId` is URL-supplied; enters ResourceDetailPage as a raw string |
| Medplum-rendered anchor → handleReferenceClick | FHIR server URL embedded in DOM; regex-extracted into navigation target |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | ResourceDetailPage `patientId` from URL interpolated into `/patients/${patientId}` | accept | `patientId` is not a security boundary: it is a path segment on routes already controlled by react-router. Malformed values yield 404 on Blaze (`readResource` error → existing error Alert). No PHI disclosure path — app is local-only. Documented as low-severity. |
| T-06-02 | Tampering | NavigationBreadcrumbs `basePath` prop interpolated into `navigate(rootHref)` | mitigate | `basePath` is set by ResourceDetailPage (trusted parent), never by external input. Logic constrains rootHref to exactly `/patients` or `/explorer` via the `startsWith('/patients/')` check — no user string reaches navigate() unescaped. Implementation detail: use exact string comparison against known prefixes, never pass `basePath` itself to navigate(). |
| T-06-03 | Information Disclosure | Cross-context leakage (patient-scoped URL accidentally surfaced in /explorer history) | accept | Before this fix, the bug leaked patientId into the /explorer trail. After this fix, navigation stays scoped to /patients. Local-only tool with single-user session — no inter-user leak risk. Regression guards (Tests B + D + F) prevent silent reintroduction. |
| T-06-04 | Denial of Service | Infinite recursion if basePath resolution loops | accept | basePath is computed synchronously in a single render; no recursion possible. Not a realistic attack surface. |
| T-06-05 | Elevation of Privilege | Basepath override via malicious component injection | accept | All call-sites of NavigationBreadcrumbs are in this repo; no plugin/extension system. New `basePath` prop is optional with a safe default (`/explorer`). |

**Note:** Threat surface for this phase is intentionally minimal — this is a routing-logic bug fix, not a new feature with new inputs. Existing reference-click sanitization (FHIR_REFERENCE_PATTERN + FHIR_ID_PATTERN in ResourceDetailPage.tsx lines 19-24) remains untouched and continues to apply.
</threat_model>
