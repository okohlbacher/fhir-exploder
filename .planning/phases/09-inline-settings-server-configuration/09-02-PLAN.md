## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → AppSettings | Modal TextInput/PasswordInput values flow into setSettings() and connection.connect() |
| Credentials in modal fields | Password and token fields are rendered as PasswordInput — masked by default, not logged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03 | Tampering | FhirSettingsModal URL input | mitigate | Call `.trim()` on formUrl and termUrl before constructing newSettings. Malformed URLs fail at fetch() inside connect() and surface as connection error dot — no server-side eval. |
| T-09-04 | Information Disclosure | PasswordInput / token field | accept | Mantine PasswordInput masks by default; show/hide toggle is user-initiated. Credentials stay in React state (memory), never written to localStorage or file. Consistent with existing SettingsPage masking behavior. |
| T-09-05 | Elevation of Privilege | setSettings() callable from modal | accept | Local-only dev tool; no multi-user model; no auth boundary to escalate across. The modal is the intended call site. |
</threat_model>
