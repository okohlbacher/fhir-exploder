## Spacing Scale

Phase 54 uses Mantine's stock `xs/sm/md/lg/xl` spacing scale, which is multiples of 4 by default (and is what every other surface in this app uses).

| Token | Value | Mantine alias | Phase 54 usage |
|-------|-------|---------------|----------------|
| xs | 4px | `gap="xs"` | Icon-to-label gap inside toolbar buttons (`<IconCopy size={14} />` → "Copy") |
| sm | 8px | `gap="sm"` | JsonModeView toolbar group gaps (chip + Anchor); validation chip Group gap |
| md | 16px | `pt="md"`, `gap="md"` | All `Tabs.Panel` top padding (`pt="md"`); KeyFieldsTable cell vertical spacing (`verticalSpacing="xs"` resolves to ~8px which is acceptable Mantine convention) |
| lg | 24px | `gap="lg"`, `p="lg"` | Outer `Stack` page-level gap between breadcrumbs / header / tabs / panel content; Summary mode internal stack |
| xl | 32px | `gap="xl"` | Not used in Phase 54 |

Exceptions: **none** — Phase 54 introduces zero spacing exceptions. All values map to existing Mantine tokens that resolve to multiples of 4 (xs=4, sm=8, md=16, lg=24, xl=32).

**Locked:**
- `<Tabs.Panel pt="md">` — all 4 panels (Pattern 2 in RESEARCH.md)
- `<Stack gap="lg">` — page-level outer container of `ResourceDetailPage`
- `<Stack gap="lg">` — Summary mode internal stack (Title → KeyFieldsTable → reverse-refs panel)
- `<Group gap="xs">` — JsonModeView left toolbar (Copy + Download buttons)
- `<Group gap="sm">` — JsonModeView right toolbar (validation chip + "Open in validator" Anchor)

## Typography

Phase 54 declares **3 sizes** (no display tier needed — page-level title comes from existing Title order=2 in the page header; Phase 54 introduces only Title order=3 inside Summary mode and small/sm body/label sizes inside the table and toolbar).

| Role | Size | Weight | Line height | Mantine token | Phase 54 usage |
|------|------|--------|-------------|---------------|----------------|
| Body | 14px | 400 | 1.5 | `<Text size="sm">` (Mantine sm = 14px) | KeyFieldsTable values; "Open in validator" anchor copy |
| Label | 14px | 500 | 1.5 | `<Text size="sm" c="dimmed">` with explicit `fontWeight: 500` style | KeyFieldsTable left column (label cell) |
| Heading (mode) | 20px | 600 | 1.3 | `<Title order={3}>` (Mantine h3) | Summary mode primary heading (`summarizeResource(r).primary`) |

**Mantine font-size resolution** (verified against Mantine 8 defaults):
- `size="xs"` = 12px
- `size="sm"` = 14px ← body + labels
- `size="md"` = 16px (NOT used in Phase 54 — reserved for future)
- `Title order={3}` = 20px

**Font weights — exactly 2:**
- `400` (regular) — body text in tables, anchor links, button labels
- `600` (semibold) — section heading (`Title order={3}`); the existing theme already applies semibold to all Mantine `Title` orders

**Line heights — exactly 2:**
- `1.5` — body and label text (Mantine default for `<Text>`)
- `1.3` — heading (Mantine default for `<Title>`)

Monospace usage (`var(--font-mono)` / `"IBM Plex Mono"`):
- `JsonViewer` body — already mono via `<JsonTreeView>` and `<JsonSyntaxHighlight>` — Phase 54 does NOT change this
- KeyFieldsTable values: **non-mono** (`<Text size="sm">`) — values are pre-formatted strings, not raw JSON; reserve mono for the JSON tab body and the generic-fallback `JSON.stringify(...).slice(0,80)` preview only

**Locked:**
- Generic fallback values in KeyFieldsTable (raw `JSON.stringify` snippets) MUST use `<Text size="sm" ff="monospace">` to visually distinguish "best-effort preview" from typed-registry human-readable values.

**Validation chip semantic colors (chip variant — `<Badge variant="light">`):**

## Layout Specifics

### Summary mode (`Tabs.Panel value="summary"`)

```
┌─ Stack gap="lg" ─────────────────────────────────────────┐
│  <Title order={3}>{summarizeResource(r).primary}</Title> │
│  <KeyFieldsTable resource={r} />                          │
│  ─ if Patient + patientId: <PatientRelatedResources/>     │
│  ─ else:                   <IncomingReferencesPanel/>     │
└──────────────────────────────────────────────────────────┘
```

- Two stacked sections (NOT side-by-side grid) — locked CONTEXT D-05
- Reverse-references panel ONLY mounts inside Summary panel (visible nowhere else)
- "References out" card — **DEFERRED to Phase 57** (RESEARCH Open Question #1)

### Human mode (`Tabs.Panel value="human"`)

Renders existing `<HumanReadableView resource={resource} />` unchanged. No new chrome.

### Graph mode (`Tabs.Panel value="graph"`)

```
┌─ Suspense fallback={<Skeleton h={600} />} ─────────┐
│  <ResourceGraphView compact />                      │
└─────────────────────────────────────────────────────┘
```

- `Suspense` fallback height = `600px` (matches React Flow canvas baseline at `ResourceGraphView.tsx:172`) — locked to prevent layout shift (CONTEXT Claude's Discretion #4)
- Pass `compact` prop to suppress `ResourceGraphView`'s own `<Title>Reference graph</Title>` + back button (RESEARCH Pitfall 2 — adds new prop to component)
- Lazy-loaded via `React.lazy(retry(() => import('./ResourceGraphView')).then(m => ({ default: m.ResourceGraphView })))`

### JSON mode (`Tabs.Panel value="json"`)

```

│  │  └──────────────────────────────┘                   │  │

│  │                  │ <Badge>chip</Badge>           │  │  │
```

## Accessibility Contract

| Concern | Provision |
|---------|-----------|
| Tab list semantics | Mantine `Tabs` renders `role="tablist"` + `role="tab"` + `role="tabpanel"` natively (locked reason for choosing Tabs over SegmentedControl) |
| Keyboard navigation between tabs | Native Mantine arrow-key navigation between `Tabs.Tab` (in addition to `1/2/3/4` global shortcuts) |
| Input-focus guard for `1/2/3/4` | `useShortcuts` hook (Phase 52) skips when INPUT/TEXTAREA/SELECT is focused — no shortcut conflict while typing in search boxes (RESEARCH Pitfall 7 noted) |
| Validation chip color-blind safety | Color is supplemented by text (`0 issues` / `N issues` / `Not validated`) — never color-only signal (matches Phase 30 design system convention) |
| Validation chip Tooltip | Provides explanatory context for unprofiled resource types (avoids misleading "validated and clean" reading) |
| Toast accessibility | Mantine notifications use `role="alert"` natively |
| Anchor for "Open in validator" | Renders as `<a href="/quality">` (Mantine Anchor + react-router Link) — keyboard reachable, screen-reader announces as link |
| Focus on tab change | Native browser behavior — selected `Tabs.Tab` receives focus when activated via click; remains where it was when activated via shortcut (Mantine handles) |
| Skeleton fallback for graph | `<Skeleton h={600} />` is announced by Mantine's internal aria-busy region (default Mantine Skeleton behavior) |
