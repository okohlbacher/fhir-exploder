    Export function `findPatientDuplicates(patients: Resource[]): { clusters: PatientDuplicateCluster[]; skippedCount: number }`:
    - Cast each to Patient
    - Extract `name[0].family`, `name[0].given[0]`, `birthDate`
    - Normalize: `.toLowerCase().trim()` on family and given
    - Skip (increment skippedCount) if any of the three is missing/empty
    - Build a Map keyed by `"${family}|${given}|${dob}"`
    - Each map entry stores `{ id: "Patient/${p.id}", resourceType: "Patient" }`
    - Filter entries to clusters with >= 2 members
    - Return `{ clusters, skippedCount }`

    Export function `normalizePatientDuplicateIssues(clusters: PatientDuplicateCluster[]): NormalizedIssue[]`:
    - For each cluster, for each patient member, emit one NormalizedIssue:
      - resourceId: member.id (already "Patient/{id}")
      - resourceType: "Patient"
      - field: "name + birthDate"
      - description: `[patient-duplicate] Exact match with ${cluster.patients.length - 1} other patients (${cluster.key})`
      - severity: "warning"

    **src/quality/contentHasher.ts** (per D-04, D-05):

    Export function `sortKeys(obj: unknown): unknown`:
    - If array: `obj.map(sortKeys)`
    - If non-null object: `Object.keys(obj).sort()` then recurse each value
    - Otherwise return as-is

    Export function `canonicalize(resource: Resource): string`:
    - Shallow clone the resource
    - Delete `id`, `meta`, `text` from the clone
    - Return `JSON.stringify(sortKeys(clone))`

    Export async function `hashResource(resource: Resource): Promise<string>`:
    - `const canonical = canonicalize(resource)`
    - `const encoded = new TextEncoder().encode(canonical)`
    - `const buffer = await crypto.subtle.digest('SHA-256', encoded)`
    - Convert ArrayBuffer to hex string (64 chars)

    Export interface `ContentHashCluster`:
    ```typescript
    export interface ContentHashCluster {
      hash: string;
      resourceType: string;
      resources: Array<{ id: string; resourceType: string }>;
    }
    ```

    Export async function `findContentHashDuplicates(resources: Resource[], resourceType: string, onProgress?: (current: number, total: number) => void): Promise<ContentHashCluster[]>`:
    - Process in batches of 25 (same as BATCH_SIZE in usePlausibilityReport)
    - For each batch: await `Promise.all(batch.map(r => hashResource(r)))`
    - Build Map keyed by hash, values are `{ id: "${resourceType}/${r.id}", resourceType }`
    - Call `onProgress?.(processed, total)` after each batch
    - Filter to clusters with >= 2 members
    - Return clusters

    Export function `normalizeContentHashIssues(clusters: ContentHashCluster[]): NormalizedIssue[]`:
    - For each cluster, for each resource member, emit one NormalizedIssue:
      - resourceId: member.id
      - resourceType: member.resourceType
      - field: "content hash"
      - description: `[content-hash] Identical content with ${cluster.resources.length - 1} other ${cluster.resourceType} resources (hash: ${cluster.hash.slice(0, 8)})`
      - severity: "warning"

    **src/quality/referenceWalker.ts** (per D-06):

    Export interface `ExtractedReference`:
    ```typescript
    export interface ExtractedReference {
      path: string;       // e.g., "Encounter.subject.reference"
      reference: string;  // e.g., "Patient/123" (always normalized to relative form)
    }
    ```

    Export function `extractReferences(resource: Resource): ExtractedReference[]`:
    - Recursive walk function `walk(obj: unknown, path: string)`:
      - Skip null/undefined
      - If array: iterate with index in path `${path}[${i}]`
      - If object with `reference` string property:
        - Skip if reference starts with `#` (contained resource -- Pitfall 3)
        - Skip if reference starts with `urn:` (bundle-internal URN -- Pitfall 2)
        - If reference starts with `http://` or `https://`: extract `Type/id` from the last two path segments (split by `/`, take last two). Skip if extraction fails.
        - Otherwise treat as relative `Type/id`
        - Push `{ path: "${path}.reference", reference: normalizedRef }`
      - Recurse into all object properties (skip `reference` key itself to avoid double-processing)
    - Start walk with `walk(resource, resource.resourceType ?? '')`

    **src/quality/referenceChecker.ts** (per D-06, D-07, D-13):

    Export async function `checkReferencesExist(client: MedplumClient, refs: ExtractedReference[], options?: { batchSize?: number; concurrency?: number; onProgress?: (current: number, total: number) => void }): Promise<Set<string>>`:
    - Default batchSize: 50, default concurrency: 5
    - Group refs by target type (split `reference` on `/`, first segment is type)
    - For each type, split IDs into batches of batchSize
    - Process batches with concurrency limit: use a simple semaphore pattern (maintain an array of active promises, wait when hitting limit)

    - Call `onProgress?.(completedBatches, totalBatches)` after each batch
    - Return Set of broken references like `"Patient/999"`

## Trust Boundaries

| Boundary | Description |

| Browser -> FHIR server | Reference existence checks send batched _id queries to the FHIR server |
| FHIR server -> Browser | Server responses parsed as JSON; malformed responses could cause crashes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Denial of Service | referenceChecker.ts | mitigate | Concurrency limit of 5 parallel batch requests (D-13). Batch size of 50 IDs per request. Sample size clamped to 1000 by SampleSizeControl. |
| T-17-02 | Denial of Service | contentHasher.ts | mitigate | Process hashing in batches of 25 with yields between batches to avoid microtask queue saturation (Pitfall 4 from RESEARCH.md). |
| T-17-03 | Denial of Service | referenceWalker.ts | mitigate | Use simple string split for Type/id extraction, not regex. Skip malformed references gracefully (no throw). |
| T-17-04 | Information Disclosure | referenceChecker.ts | accept | Broken reference messages include the target reference string (e.g., "Patient/123"). This is expected behavior for a local diagnostic tool -- no PII leakage concern for a single-user local app. |
| T-17-05 | Tampering | contentHasher.ts | accept | SHA-256 used for fingerprinting/dedup, not security. No integrity guarantees needed -- this is a read-only diagnostic display. |
</threat_model>
