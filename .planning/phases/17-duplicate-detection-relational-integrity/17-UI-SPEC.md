# Phase 17 — UI Design Contract

> Visual and interaction contract for the Duplicate Detection & Relational Integrity phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 17 extends the quality dashboard from 6 tabs to 8, adding "Duplicates" (patient matching + content hash deduplication) and "References" (broken references + orphan resources) as new tab panels. Both tabs follow the established hook-panel-drilldown pattern from Phases 15/16. All new findings normalize into `NormalizedIssue` and render via the shared `ResourceIssueTable` component. No new dependencies, no new design tokens, no theme changes.

## Interaction Contracts

### I-01: Eight-Tab Navigation

**Trigger:** User views the quality dashboard.

**Default state:** "Counts" tab is active (unchanged from current behavior).

**Behavior:**
1. Tab bar expands from 6 to 8 tabs: Counts | Completeness | Coding Coverage | Validation | Plausibility | Lab Ranges | Duplicates | References.
2. All tabs use `keepMounted` to preserve computed state when switching.
3. Tab order matches the Kahn et al. framework progression: structural counts, then conformance (completeness, coding, validation), then plausibility, then lab ranges, then uniqueness (duplicates), then relational integrity (references).
4. New tabs render their panels identically to existing tabs -- `<Tabs.Panel value="..." pt="md" keepMounted>`.
5. New tab value identifiers: `duplicates`, `references`.

**Mantine API:** Extend existing `<Tabs defaultValue="counts" keepMounted>` with two additional `<Tabs.Tab>` and `<Tabs.Panel>` entries.

### I-02: Duplicates Panel Interaction

**Trigger:** User clicks the "Duplicates" tab.

**Default state:** Panel shows a resource type selector (for content hash scope, defaulting to first type), a "Run duplicate checks" button, and empty results area.

**Behavior:**
1. Resource type `Select` (searchable, `style={{ minWidth: 240 }}`) scopes content hash deduplication. Patient duplicate detection always runs against Patient resources regardless of this selector.
2. Check-category filter `Select` with options: "All checks", "Patient duplicates", "Content hash duplicates". Filters `NormalizedIssue[]` by matching category prefix in the description field.
3. "Run duplicate checks" `Button` (variant="filled"). Disabled when `status === 'running'`.
4. While running: `Progress` bar (animated) with phase-specific text:
   - Phase 1: "Matching patients ({current}/{total})..."
   - Phase 2: "Hashing {type} resources ({current}/{total})..."
   - Cancel button: "Stop duplicate check" (`variant="subtle"` `color="red"` `leftSection={<IconX size={14} />}`).
5. On completion: summary section with:
   - Text line: "{N} patient duplicate clusters ({M} patients involved)" with orange badge.
   - Text line: "{N} content hash clusters in {type} ({M} resources involved)" with violet badge.
   - If patients were skipped: dimmed text "({K} patients skipped -- missing name or birthDate)" below patient cluster count.
   - Sample size note: dimmed text "Checked {N} of {M} patients. Increase sample size for more thorough detection."
6. Below summary: `ResourceIssueTable` with all normalized duplicate issues (filtered by category if not "All checks").
7. Each issue row links to `/explorer/{type}/{id}` via the standard ResourceIssueTable pattern.

**Controls layout:** `Group` with `align="flex-end"` `gap="md"`, wrapping the Select, filter, and Button. Wrapped in a `Paper withBorder p="md" radius="sm"`.

### I-03: References Panel Interaction

**Trigger:** User clicks the "References" tab.

**Default state:** Panel shows a resource type selector (defaulting to first type), a "Run reference checks" button, and empty results area.

**Behavior:**
1. Resource type `Select` (searchable, `style={{ minWidth: 240 }}`) scopes which resource type to check references for.
2. Check-category filter `Select` with options: "All checks", "Broken references", "Orphan resources". Filters `NormalizedIssue[]` by matching category prefix.
3. "Run reference checks" `Button` (variant="filled"). Disabled when `status === 'running'`.
4. While running: `Progress` bar (animated) with two phases:
   - Phase 1: "Checking references in {type} ({current}/{total})..."
   - Phase 2: "Verifying reference targets ({current}/{total} batches)..."
   - Cancel button: "Stop reference check" (`variant="subtle"` `color="red"` `leftSection={<IconX size={14} />}`).
5. On completion: summary section with:
   - Text line: "{N} broken references found" with red badge.
   - Text line: "{N} orphan resources found" with yellow badge.
6. Below summary: `ResourceIssueTable` with all normalized reference issues (filtered by category if not "All checks").
7. Broken reference severity is `warning` (per D-07: data may be partitioned across servers).

**Controls layout:** Same as DuplicatesPanel -- `Group` with `align="flex-end"` `gap="md"` in `Paper withBorder p="md" radius="sm"`.

### I-04: Drill-Down Navigation (Duplicates / References)

**Trigger:** User clicks a resource in the drill-down table, or navigates via deep link.

**Behavior:**
1. Duplicates drill-down navigates to `/quality/duplicates`. References drill-down navigates to `/quality/references/:type`.
2. Drill-down page layout matches existing CompletenessDrillDown pattern: back button (`variant="subtle"` `leftSection={<IconArrowLeft />}`), title, then `ResourceIssueTable`.
3. Back button copy: "Back to Duplicates" or "Back to References".
4. Drill-down title: "Duplicate Detection -- Drill-down" or "{type} -- Reference Integrity drill-down".
5. Browser back button returns to the dashboard with tab state preserved (React Router handles this).
6. Drill-down pages access `QualityOutletContext` via `useOutletContext()` and run their respective hooks to generate issues.

## Empty & Error States

### Empty State: No Duplicates Detected

**When:** Both patient duplicate detection and content hash deduplication return zero clusters after a run completes.

**Render:** Mantine `Alert` with `color="green"` `variant="light"`.
- Icon: `IconCheck` from `@tabler/icons-react`.
- Title: "No duplicates detected"
- Body: "No duplicate patients or resources found in the sample. Increase the sample size to check more resources."

### Empty State: No Reference Issues

**When:** Both broken reference checking and orphan detection return zero issues after a run completes.

**Render:** Mantine `Alert` with `color="green"` `variant="light"`.
- Icon: `IconCheck`.
- Title: "No reference issues found"
- Body: "All sampled references resolve correctly and no orphan resources detected. Increase the sample size to check more resources."

### Empty State: No Patients on Server

**When:** Server has zero Patient resources (or Patient is excluded from cohort), preventing patient duplicate detection.

**Render:** Mantine `Alert` with `color="blue"` `variant="light"`.
- Icon: `IconInfoCircle`.
- Title: "No Patient resources found"
- Body: "No Patient resources found on this server. Patient duplicate detection requires Patient resources with name and birthDate fields."

### Error State: Check Failure

**When:** Hook returns `'error'` state (network failure, FHIR server timeout).

**Render:** Mantine `Alert` with `color="red"` `variant="light"`.
- Icon: `IconAlertTriangle`.
- Copy (duplicates): "Failed to run duplicate checks. Check your FHIR server connection and try again."
- Copy (references): "Failed to run reference checks for {type}. Check your FHIR server connection and try again."

### Loading State

**When:** Check is in progress (`status === 'running'`).

**Render:** `Paper withBorder p="sm" radius="sm"` containing a `Stack gap="xs"` with `aria-live="polite"`:
- `Text size="sm"` with progress message (panel-specific, see Copywriting Contract)
- `Progress` bar (animated, `value={pct}`)
- Cancel `Button` to the right of the progress text (`variant="subtle"` `color="red"` `leftSection={<IconX size={14} />}`)

Same pattern as PlausibilityPanel progress section.

### Cancellation State

**When:** User cancels a running check (`status === 'cancelled'`).

**Render:** Mantine `Alert` with `color="yellow"` `variant="light"` `icon={<IconAlertTriangle size={20} />}`.
- Copy: see Copywriting Contract cancelled state entries.
- Followed by partial results in `ResourceIssueTable` (if any issues were found before cancellation).

## NormalizedIssue Mapping

All findings normalize to the existing `NormalizedIssue` interface:

### Patient Duplicates (DQ-07)

Each member of a duplicate cluster generates one issue:
- `resourceId`: `"Patient/{id}"`
- `resourceType`: `"Patient"`
- `field`: `"name + birthDate"`
- `description`: `"[patient-duplicate] Exact match with {N} other patients ({family}|{given}|{birthDate})"`
- `severity`: `"warning"`

### Content Hash Duplicates (DQ-08)

Each member of a hash cluster generates one issue:
- `resourceId`: `"{Type}/{id}"`
- `resourceType`: `"{Type}"`
- `field`: `"content hash"`
- `description`: `"[content-hash] Identical content with {N} other {type} resources (hash: {first8chars})"`
- `severity`: `"warning"`

### Broken References (DQ-09)

Each broken reference generates one issue:
- `resourceId`: `"{SourceType}/{sourceId}"`
- `resourceType`: `"{SourceType}"`
- `field`: `"{field.path}.reference"` (e.g., `"Encounter.subject.reference"`)
- `description`: `"[broken-ref] Reference {targetType}/{targetId} does not resolve on this server"`
- `severity`: `"warning"`

### Orphan Resources (DQ-10)

Each orphan resource generates one issue:
- `resourceId`: `"{Type}/{id}"`
- `resourceType`: `"{Type}"`
- `field`: `"{expected.reference.path}"` (e.g., `"Observation.subject"`)
- `description`: `"[orphan] Missing required reference: {field}"`
- `severity`: `"warning"`

## Accessibility Notes

- New tabs ("Duplicates", "References") inherit Mantine Tabs ARIA semantics (`role="tab"`, `role="tabpanel"`, keyboard navigation) automatically.
- Progress indicators use `aria-live="polite"` (match existing PlausibilityPanel pattern).
- All filter controls (`Select`) have explicit `label` props that serve as accessible names.
- Check-category badges are decorative summaries and do not require interactive ARIA roles.
- Empty state and error alerts use Mantine `Alert` with implicit `role="alert"` semantics.
- Duplicate cluster count and skipped patient info use plain `Text` elements -- screen readers will read them in document order.
