## Spacing Scale

Inherits Mantine default spacing scale from Phase 1/2 (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge spacing, timeline dot offset |
| sm | 8px | Compact element spacing, tab internal padding, table cell padding |
| md | 16px | Default element spacing, card padding, PatientHeader internal spacing |
| lg | 24px | Section gaps between patient detail sections (Stack gap="lg") |
| xl | 32px | Page-level vertical padding, gap between patient header and tab content |
| 2xl | 48px | Empty state vertical padding |
| 3xl | 64px | Not used in this phase |

Exceptions: Timeline left gutter is 40px (accommodates date label + vertical line). PatientHeader component uses its own internal spacing (Medplum-controlled, not overridden).

## Typography

Inherits two-weight system from Phase 1/2: 400 (regular) and 600 (semibold).

| Role | Size | Weight | Line Height | Mantine Token |
|------|------|--------|-------------|---------------|
| Body | 14px | 400 (regular) | 1.55 | sm |
| Label | 14px | 600 (semibold) | 1.55 | sm, fw={600} |
| Heading | 20px | 600 (semibold) | 1.2 | Title order={2} |
| Subheading | 16px | 600 (semibold) | 1.3 | Title order={4} |

Usage in this phase:
- **Body (sm, 400):** Patient list cell text, clinical data values, timeline entry descriptions, resource property values
- **Label (sm, 600):** MII module tab labels (e.g., "Diagnose"), column headers in patient-scoped tables, timeline type badges, search parameter labels
- **Heading (order=2, 600):** Not used standalone (PatientHeader renders the patient name at its own size)
- **Subheading (order=4, 600):** MII module tab subtitle (FHIR resource type), section headers within timeline, "FHIR Resources" / "MII Modules" toggle labels

## Interaction Contracts

### Patient Search Flow (PTNT-01)
1. User clicks "Patients" in sidebar, arrives at `/patients`
2. Search fields shown: name (TextInput), identifier (TextInput), birthDate (DateInput or TextInput with FHIR date format)
3. User fills fields, clicks "Search Patients" or presses Enter
4. URL updates: `/patients?name=Mueller&birthdate=1980`
5. Results load with Skeleton placeholders, then render in patient table
6. Clicking a patient row navigates to `/patients/{id}`

### Patient Detail Navigation (PTNT-02, PTNT-03)
1. Patient detail page loads with PatientHeader banner at top
2. Below header: SegmentedControl toggle defaulting to "MII Modules"
3. MII Modules view shows Tabs component with six tabs
4. Default active tab: first tab with data (Diagnose if available, otherwise first non-empty)
5. Each tab loads patient-scoped resources via FHIR search: `{ResourceType}?patient={id}`
6. Clicking a resource row navigates to `/patients/{patientId}/{resourceType}/{resourceId}` which renders Phase 2 resource detail view

### MII Module Tab Structure (PTNT-03, D-05)
Each tab renders:
1. Tab label: German name in semibold, FHIR resource type in dimmed text below
2. Tab content: ResourceTable showing patient-scoped resources of that type
3. Empty tab: "No {German module name} data found for this patient."
4. Loading tab: 3-5 Skeleton rows

### Clinical Timeline (PTNT-04, D-07)
1. Timeline is an additional tab labeled "Zeitleiste" (Timeline) at the end of the MII module tabs
2. Aggregates Encounter, Condition, Procedure, and Observation resources for the patient
3. Entries sorted by date descending (most recent first)
4. Each entry shows: date (left), color-coded type Badge, resource summary text
5. Card-style entries (Paper with left border color matching type badge)
6. Clicking an entry navigates to the resource detail view
7. Loading state: 5 Skeleton entries with placeholder badges

### MII vs FHIR Toggle (PTNT-05, D-09)
1. SegmentedControl with two segments: "MII Modules" | "FHIR Resources"
2. Default: "MII Modules" (D-10)
3. "FHIR Resources" view shows a list of all resource types linked to this patient with counts
4. Each resource type row is clickable, expanding to show a ResourceTable of those resources
5. Resource types not covered by MII modules still appear in "FHIR Resources" view (Claude's Discretion: this is how uncovered types are handled)
6. Toggle state persisted in component state for the session (D-10)

### Reference Navigation (reuses Phase 2 pattern)
1. Reference fields in patient-scoped tables render as blue links
2. Clicking navigates to resource detail with breadcrumb trail
3. Breadcrumb format: "Patients > Patient/{name} > {ResourceType}/{id}"

## Layout Contract

**Primary focal point:** On the patient list page, the search results table is the focal point. On the patient detail page, the tab content panel (MII module table or timeline) is the focal point.

### Patient List Page Structure
```
+--sidebar--+--main-content-area-----------------------------------+
|            | [Page Title: "Patients"]                             |
|            | [Search Fields: Name | Identifier | Birth Date]     |
|            | [Search Patients button]                             |
|            | [Results status: "Showing 1-20 of 1,234"]           |
|            | [Patient Table (SearchControl)]  <-- FOCAL           |
|            | [Pagination: < Previous | page size | Next >]        |
+------------+-----------------------------------------------------+
```

### Patient Detail Page Structure (MII Modules view)
```
+--sidebar--+--main-content-area-----------------------------------+
|            | [Breadcrumbs: Patients > Patient Name]               |
|            | [PatientHeader banner]                               |
|            |                                                      |
|            | [SegmentedControl: MII Modules | FHIR Resources]    |
|            |                                                      |
|            | [Tabs: Diagnose|Prozedur|Laborbefund|Medikation|     |
|            |        Fall|Consent|Zeitleiste]                      |
|            | [Tab content: Resource table]  <-- FOCAL             |
|            | [Pagination if needed]                               |
+------------+-----------------------------------------------------+
```

### Patient Detail Page Structure (FHIR Resources view)
```
+--sidebar--+--main-content-area-----------------------------------+
|            | [Breadcrumbs: Patients > Patient Name]               |
|            | [PatientHeader banner]                               |
|            |                                                      |
|            | [SegmentedControl: MII Modules | FHIR Resources]    |
|            |                                                      |
|            | [Resource Type List with counts]                     |
|            |   Condition (12) [expandable]                        |

|            |   Observation (45) [expandable]                      |
|            |   ... (all linked types)                             |
|            | [Expanded: ResourceTable]  <-- FOCAL                 |
+------------+-----------------------------------------------------+
```

### Timeline Entry Structure
```
+--date-column--+--entry-card----------------------------------------+
| 2024-03-15    | [Badge: Diagnose]  Diabetes mellitus Typ 2         |
|               | Condition/abc123                                   |
+---------------+----------------------------------------------------+
| 2024-03-14    | [Badge: Fall]  Ambulanter Kontakt                  |
|               | Encounter/def456                                   |
+---------------+----------------------------------------------------+
```

Timeline entries use Paper component with 3px left border colored by resource type. Date column is 100px fixed width. Entry card fills remaining space.

Main content area uses `Stack gap="lg"` consistent with Phase 1/2 patterns.

## States Matrix

| State | Visual Treatment |
|-------|------------------|
| Loading patient list | Skeleton rows (5 rows of Skeleton height=40) in table area |
| Loading patient detail | PatientHeader skeleton (Skeleton height=80) + tab skeleton (3 Skeleton rows) |
| Loading module tab content | 3-5 Skeleton rows within the active tab panel |
| Loading timeline | 5 Skeleton entries (Skeleton height=60 each with left border placeholder) |
| Patient list empty (no search) | Centered empty state with "Browse Patients" heading and body text |
| Patient list empty (with search) | Centered empty state with "No patients found" heading and suggestion |
| Module tab empty | Centered text: "No {module name} data found for this patient." |
| Timeline empty | Centered text: "No clinical events recorded for this patient." |
| FHIR resources view empty | Centered text: "No linked resources found for this patient." |
| Search error | Alert color="red" with error message and "Retry" button |
| Patient not found | Alert color="red" with "Patient not found" message and back link to patient list |
| Patient detail load error | Alert color="red" with error message and "Retry" button |
| Server disconnected | Redirect to dashboard with connection error (reuse Phase 1 error handling) |
| Pagination at start | "Previous" button disabled |
| Pagination at end | "Next" button disabled |
| Tab switching | No loading indicator if data is cached; Skeleton rows if fetching |
