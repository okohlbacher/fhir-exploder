         ```typescript
         const patientLinkedTypes = useMemo(() => {

             ?.filter(r => r.searchParam?.some(p => p.name === 'patient' || p.name === 'subject'))
             ?.map(r => r.type)
             ?.filter((t): t is string => !!t)
             ?.sort() ?? [];
         }, [capability]);
         ```

       - State: `counts: Record<string, number | 'loading' | 'error'>` initialized with all types set to `'loading'`
       - useEffect: For each resource type in `patientLinkedTypes`, fetch count:
         ```typescript
         client.search(type, `patient=Patient/${patientId}&_summary=count`)
           .then(bundle => setCounts(prev => ({ ...prev, [type]: bundle.total ?? 0 })))
           .catch(() => setCounts(prev => ({ ...prev, [type]: 'error' })));
         ```
       - Only fetch on first mount (patientId + patientLinkedTypes as deps)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Patient ID from URL -> FHIR query | patientId from route params used in FHIR read and search queries |
| Reference click -> navigation | Clicked FHIR references extracted and used for in-app navigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering | PatientDetailPage patientId | mitigate | patientId from URL params passed to `client.readResource('Patient', patientId)` which validates via MedplumClient HTTP request; invalid IDs return 404 handled by error state |
| T-03-04 | Tampering | MiiModuleTab search filter | mitigate | patient filter value constructed as `Patient/${patientId}` -- patientId is from URL params and encoded by SearchControl/MedplumClient; module.patientSearchParam comes from hardcoded MII_MODULES config (not user input) |
| T-03-05 | Tampering | FhirResourcesView reference navigation | mitigate | Resource type comes from CapabilityStatement (server-provided), resource ID from SearchControl click event (server-provided); reuses Phase 2 ResourceDetailPage which has FHIR reference validation (T-02-08 pattern with isValidFhirReference) |
| T-03-06 | Information Disclosure | Patient data display | accept | Local-only app; user has full FHIR server access by design; no cross-user data exposure |
</threat_model>
