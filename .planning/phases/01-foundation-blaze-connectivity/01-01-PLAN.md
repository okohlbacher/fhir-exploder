2. **Create `src/config/settings.ts`** -- Settings loader with defaults per D-05, D-06:
- Export `DEFAULTS` constant: `{ fhir: { serverUrl: 'http://localhost:8080/fhir', auth: { mode: 'open' } } }`
- Export `loadSettings()` async function that:
  - Fetches `/settings.yaml` via `fetch('/settings.yaml')`
  - Parses with `js-yaml` `load()` function
  - Deep-merges with DEFAULTS (so missing fields get defaults)
  - Returns `{ settings: AppSettings; usingDefaults: boolean }`
  - On 404 or parse error: returns `{ settings: DEFAULTS, usingDefaults: true }`

**NOTE on D-05 (settings.yaml location):** D-05 specifies settings.yaml at the project root (`./settings.yaml`). However, Vite SPAs cannot read the local filesystem -- browser `fetch()` can only access files served by the dev server. The file is placed in `public/settings.yaml` so Vite serves it at `/settings.yaml`. This is a technical necessity, not a deviation from user intent. The executor MUST note this in the SUMMARY so the user is informed. The user edits `public/settings.yaml` (which is still in the project, just one directory deeper).
