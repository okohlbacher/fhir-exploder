## Before / After (RenderValue dispatch order)

**Before (buggy):**
```
Reference → CodeableConcept → Coding (line 121)  ← UCUM Quantity matched here, value dropped
          → HumanName → Identifier → Period
          → Quantity (line 176)  ← UNREACHABLE for UCUM-coded inputs
          → generic-nested-object fallback
```

**After (fixed):**
```
Reference → CodeableConcept → Quantity-shape (NEW)  ← UCUM Quantity matched first; value + unit rendered
          → Coding → HumanName → Identifier → Period
          → generic-nested-object fallback
```

The new Quantity-shape branch detects via `typeof obj.unit === 'string' || (typeof obj.value === 'number' && !obj.coding)` to disambiguate from Identifier (whose `value` is a string) and CodeableConcept (which has `coding`).

## Decisions Made

- **Quantity detection over presence-of-`code`:** Used `typeof obj.unit === 'string' || (typeof obj.value === 'number' && !obj.coding)` rather than excluding `obj.code` from the Coding branch, because the Quantity-first reorder is a structural fix (the dispatcher is order-sensitive by design) and the additive shape-test is more robust against future Coding-shape extensions.
- **Em-dash for unit-only / empty:** A unit string alone (e.g. `mg/dL` with no value) is not a meaningful measurement. Rendering em-dash matches the null/undefined branch's existing convention and prevents misleading bare-unit display.
- **HUMAN-UAT append-only:** Per Phase 38 D-03, original `result: fail` markers preserved untouched; new Phase 38.2 annotation appended after the existing Phase 38.1 annotation to maintain the chronological audit trail.
