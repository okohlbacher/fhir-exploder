# Phase 35 — UI Design Contract

> Visual and interaction contract for Phase-30 UAT Follow-ups (UAT-FU-01/02/03) + Per-Type Quality Matrix (UAT-FU-05).
> Generated by gsd-ui-researcher (--auto mode); to be validated by gsd-ui-checker; consumed by gsd-planner, gsd-executor, gsd-ui-auditor.

This phase ships zero new design tokens. It composes existing Mantine 8 primitives (`Tooltip`, `Modal`, `Tabs`, `Card`, `Table`, `Progress`, `Badge`, `Code`, `Skeleton`) inside the Phase 30 redesign chrome (IBM Plex + indigo + warm neutrals + 60/30/10) into four discrete deliverables. The UI-SPEC anchors the four scope blocks to four predictable visual contracts so the executor cannot drift.

## Typography

Inherits Phase 30 redesign tokens (IBM Plex Sans + Mono). Phase 35 adds zero new type scales; the four roles below cover every render site across UAT-FU-01/02/03/05.

| Role | Size | Weight | Line Height | Family | Where used in Phase 35 |
|------|------|--------|-------------|--------|------------------------|
| Body | 14px (`size="sm"`) | 400 | 1.45 | IBM Plex Sans | Status `Badge` text in SearchResultsPage rows; Modal body copy; Tooltip text; matrix-row Resource type cell, "Issues" integer cell, Modal-trigger Button label, Extensions row "Value summary" cell |
| Label | 12px (`size="xs"`) | 600 (uppercase letter-spacing 0.5px) | 1.4 | IBM Plex Sans | Matrix card Card-title `Quality by resource type`; SortableTh column headers (delegated to existing component which uses `size="sm" fw={600}` — preserved); "Extensions" section heading |
| Mono | 12-13px (`size="xs"` / `size="sm"` ff="monospace") | 400 | 1.4 | IBM Plex Mono + `font-variant-numeric: tabular-nums` | Resource type names in matrix Resource-type column (matches `ResourceCountsPanel` sibling); URL fragment in Extensions table; Modal title (full extension URL) |
| Numeric | 14px (`size="sm"` `fw={600}`) | 600 | 1.4 | IBM Plex Sans + `tabular-nums` for matrix percent cells | Matrix percent cells (Complete %, Coverage %, Validation %, References %, Dup); Issues integer count |

**Only two font weights declared:** 400 (body, mono, status text) and 600 (labels, headings, numerics). No italic, no 500/700.

**Line-height contract:**
- Body 1.45 (matches `tokens.css` body baseline)
- Label 1.4
- Numeric 1.4 (kept tight so the inline Progress bar visually anchors below the percent number)

**Em-dash convention (locked, derived from Phase 18 D-14 invariant + Phase 35 RESEARCH P-05):**
- All "no data yet" cells render `—` (em-dash) at body size + `c="dimmed"` (var `--ink-3` or Mantine `c="dimmed"`)
- NEVER render `0%` for sparse byType — `0%` is a real signal (means "we measured and got 0"); em-dash means "we have not measured this yet"
- This is the single most important visual contract in the matrix; the auditor MUST grep for `0%` literal in matrix cell render code.

### Threshold-breach color contract (matrix-specific)

Per D-18 + RESEARCH §isBreached curried hook usage, breach coloring follows the established `OverviewStrip`/`MetricTile` pattern:

| Cell state | Numeric `<Text>` color | `<Progress>` color |
|------------|------------------------|--------------------|
| Within threshold (or threshold not configured for metric) | undefined (default `--ink`) | `"indigo"` (default; resolves to `indigo.6` per `primaryShade: 6`) |
| Breached (per `useThresholds().isBreached(metricKey, value)`) | `"red.6"` | `"red"` (resolves to `red.6`) |
| Sparse (no `byType` entry yet) | `c="dimmed"` em-dash, NO Progress bar rendered | n/a |
| Loading (`useResourceCounts` returns `'loading'` for the row) | `<Skeleton height={14} width={40}>` | `<Skeleton height={6} width={120}>` |

**No new color tokens introduced.** The matrix re-uses Mantine `red.6` already in the theme via the breach precedent. No threshold-breach toast, no banner — visual cell color only (consistent with Phase 18 D-15 visual-only mandate).

## Interaction Contract

Phase 35 introduces four new interaction primitives. Every other Phase 30-34 primitive is preserved unchanged.

### 1. Identifier-system Tooltip (UAT-FU-02)

| State | Visual |
|-------|--------|
| Idle | Identifier `value` text rendered normally; cursor `help` on hover over the value cell signals additional info |
| Hover (≥150ms per Mantine default `openDelay`) | Tooltip appears via portal (Mantine 8 `withinPortal: true` default); arrow points to the value cell; full system URL displayed in Tooltip body |
| Focus (keyboard tab to value cell) | Tooltip appears (Mantine default `events={{ hover: true, focus: true, touch: false }}`) |
| Mobile / touch | Tooltip suppressed (Mantine touch default) — system URL accessible via `<Modal>` view of the resource if needed; acceptable accessibility tradeoff (FHIR Exploder is desktop-first per PROJECT.md) |

**Implementation note for executor:** Mantine `<Tooltip>` defaults to `withinPortal: true` — tests that scope queries with `within(cell)` will fail (RESEARCH Pitfall P-13). Use `screen.getByRole('tooltip')` or `screen.getByText(systemUrl)` in tests.

### 2. Address-extension Modal (UAT-FU-02)

| State | Visual |
|-------|--------|
| Idle | Address row in `ResourcePropertyTable` shows the readable address fields normally; a `<Button size="xs" variant="light">View</Button>` sits in the row's value cell where the inline JSON dump used to be |
| Click `[View]` | Mantine `<Modal>` opens via `useDisclosure()`, `size="lg"`, title = extension display name (or trimmed URL) |
| Modal open | Body renders `<Code block fz="xs" style={{ maxHeight: 500, overflowY: 'auto' }}>` containing `JSON.stringify(extension, null, 2)` |
| Modal close (overlay click, ESC, or X button) | `useDisclosure` closes; focus returns to triggering Button per Mantine default focus trap |

### 3. Bottom Extensions Section (UAT-FU-02)

| State | Visual |
|-------|--------|
| Resource has no extensions OR empty extension array | Section NOT RENDERED — silent hide |
| Resource has 1+ extensions | Section renders BELOW the existing `<ResourcePropertyTable>` inside `HumanReadableView`'s `<ScrollArea>`; heading `Extensions` (`fw={600}` `size="sm"`); table with 3 columns (URL fragment, Value summary, [View] button) |
| Per-row click on `[View]` | Same Modal pattern as #2 above; Modal title = trimmed URL fragment (last 2 path segments), body = JSON pretty-print of that extension |
| Multiple extensions with same `url` | Deduped to first occurrence (per RESEARCH code example); duplicates silently dropped — acceptable since the View modal shows full JSON of the first |

**`ResourcePropertyTable` MUST add `'extension'` to its `SKIP_KEYS` Set** so the bottom Extensions section is the SOLE renderer of resource-level extensions (per RESEARCH integration map line 631). Property-level extensions (e.g. `_birthDate.extension`) stay inline in their property row — they are NOT part of `Resource.extension[]`.

### 4. ResourceDetailPage Tab Reduction (UAT-FU-03)

| State | Visual |
|-------|--------|
| Initial mount | Tabs renders 2 `<Tabs.Tab>` elements: `Human-readable` (value `human-readable`) + `JSON` (value `developer`). Active tab defaults to `human-readable` (UNCHANGED from existing `useState('human-readable')`). |

| Keyboard `1` | jumps to `human-readable` (UNCHANGED) |
| Keyboard `2` | jumps to `developer` (REMAPPED — was `clinical-raw` → now skips deleted middle tab and lands on JSON) |

**The `<div onClick={handleReferenceClick}>` wrapper at line 190 is preserved untouched.** Only the middle `<Tabs.Tab>` and `<Tabs.Panel>` are deleted; click-delegation surface stays intact (RESEARCH Pitfall P-12).

### 5. Per-Type Quality Matrix Card (UAT-FU-05)

| State | Visual |
|-------|--------|
| Counts loading | Card renders with skeleton rows matching `ResourceCountsPanel` row count (uses same `useResourceCounts` source); per-row, all 7 numeric cells render `<Skeleton>` |
