# Phase 53 — UI Design Contract

> Visual and interaction contract for the Peek Call-Site Expansion. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase scope (visual surfaces):**
> 1. `JsonPeekDrawer` — extend with **error body state** (`Reference unresolvable`) + reference-string title fallback (`ff="monospace"`). Existing 420px / no-overlay drawer config from Phase 52 is preserved unchanged.
> 2. `PatientListPage` `PatientRow` — add `tabIndex=0` + indigo focus ring (mirror Phase 52 `SearchResultsPage` pattern byte-identical).
> 3. `ReferenceLink` Anchor — add Cmd/Ctrl+click intercept; **no visual change at rest** (no new tooltip text, no new icon, no cursor change — Cmd modifier is a discoverable platform convention).
> 4. `RelatedResourcesPanel` Card — add Cmd/Ctrl+click intercept; **no visual change at rest** (existing `cursor: pointer` already signals interactivity).
>
> **Not in scope:** drawer toolbar (Copy/Download/validate chip → Phase 54), 4-mode shell (Phase 54), Explorer density controls (Phase 55), PatientListPage-as-lens rebrand (Phase 57), hover-peek tooltip on reference chips (explicitly out of scope per REQUIREMENTS).

## Interaction Contract

Phase 53 introduces three new interactions on top of Phase 52's contract. All bind to specific elements; all respect the input-focus guard.

### Keyboard — page-scoped

| Key | When | Action | Guard | Source |
|-----|------|--------|-------|--------|
| `J` | A `<Table.Tr>` in `PatientListPage` is `document.activeElement` (or contains it) AND `tag !== 'INPUT'/'TEXTAREA'/'SELECT'` | Open drawer with that patient resource; capture `originElement = document.activeElement` | input-focus guard (`useShortcuts`) | PEEK-05 surface 2, CONTEXT D-07 |
| `J` | `PatientListPage` mounted, no row focused | **silent no-op** | row-focus guard (`focusedPatient === null` early-return) | CONTEXT D-07 |
| `J` | `PatientListPage` mounted, INPUT in filter card focused | **silent no-op** | `useShortcuts` input-focus guard | RESEARCH Pitfall 3 |
| `Esc` | Drawer is open (success OR error state) | Close drawer; call `originElement.focus()` to return focus to originating row/anchor/card | Mantine `closeOnEscape={true}` | inherited PEEK-02 |
| `Enter` | Drawer is open AND in **success** state AND `tag !== 'BUTTON'/'A'/'INPUT'/'TEXTAREA'/'SELECT'` | Navigate to `/explorer/{type}/{id}?mode=json`; close drawer | inherited PEEK-03 |
| `Enter` | Drawer is open AND in **error** state (`peekState.resource === null`) | **silent no-op** (no resource to navigate to) | RESEARCH Open Question 2 (locked answer) + CONTEXT D-05 |

### Mouse — Cmd/Ctrl+click intercepts

| Element | Modifier | Action | Result |
|---------|----------|--------|--------|
| `ReferenceLink` Anchor — `status === 'resolved'` | `metaKey \|\| ctrlKey` + click | `e.preventDefault() + e.stopPropagation()` + `openPeek(resource, document.activeElement)` | Drawer opens with resolved Resource |
| `ReferenceLink` Anchor — `status === 'failed'` | `metaKey \|\| ctrlKey` + click | `e.preventDefault() + e.stopPropagation()` + `openPeekError(rawText, document.activeElement)` | Drawer opens with error body, title = raw reference (mono) |
| `ReferenceLink` Anchor — `status === 'pending'` | `metaKey \|\| ctrlKey` + click | (handler not attached in pending render path; pending renders `<Text>`, not `<Anchor>`) | No-op (anchor doesn't exist yet) |
| `ReferenceLink` Anchor — fragment-resolved (contained refs) | `metaKey \|\| ctrlKey` + click | Same as `resolved` path — `openPeek(containedResource, ...)` | Drawer opens with the contained Resource (per RESEARCH Open Question 3 recommendation) |
| `ReferenceLink` Anchor — any path | plain click (no modifier) | Existing behavior preserved — `handleReferenceClick` in `ResourceDetailPage` intercepts for in-app navigation | No drawer, normal navigation |
| `RelatedResourcesPanel` Card | `metaKey \|\| ctrlKey` + click | `e.stopPropagation()` + async fetch first result; if found → `openPeek(first, ...)`, else / on rejection → `openPeekError('{Type}?{param}={refValue}', ...)` | Drawer opens; brief async delay acceptable (no spinner per CONTEXT D-13) |
| `RelatedResourcesPanel` Card | plain click (no modifier) | Existing behavior preserved — `navigate(onCardNavigate(e))` | No drawer, normal navigation to filtered explorer |
| Drawer `[Open full →]` button | click | (inherited Phase 52) | Navigate to `?mode=json` and close drawer |
| Drawer `×` close button | click | (inherited Phase 52) | Close drawer + restore focus |
| Drawer body (error state) | click | None — `<Text c="dimmed">` is inert text | Nothing |

### Focus management — drawer lifecycle (extended for error state)

| Phase | Behavior | Implementation |
|-------|----------|----------------|
| Pre-open (PatientListPage J) | User focuses `<Table.Tr>` via keyboard (`Tab`) or pointer | `tabIndex={0}` on each `Table.Tr` in `PatientRow`; visible focus ring per Color section |
| Pre-open (ReferenceLink Cmd+click) | User has the Anchor as `document.activeElement` after focusing the page | (no new affordance — existing Anchor focus-on-click behavior) |
| Pre-open (RelatedResourcesPanel Cmd+click) | User has the Card as `document.activeElement` (Mantine Card with onClick is focusable in modern browsers via tabIndex implicit), or document.body if pointer-clicked | (no new affordance — existing focus model) |
| Open (success) | `openPeek(resource, originElement)` stores `originElement` in context state | inherited |
| Open (error) | `openPeekError(referenceText, originElement)` stores `originElement` + `referenceText` + `error: 'Reference unresolvable'` + sets `resource: null` | new this phase (CONTEXT D-04) |
| Open (in-drawer) | `trapFocus={true}` keeps Tab cycling inside drawer | inherited |
| Close | `returnFocus={false}`; manual `originElement?.focus()` after Mantine animation completes (queueMicrotask) | inherited |
| Content swap (open → different resource via Cmd+click) | Drawer stays mounted; `peekState` updates atomically; no animation; `originElement` updates | inherited PEEK-02 |
| Error → success transition | `peekState.resource: null → Resource`; drawer body re-renders from `<Text>` to `<JsonViewer>`; `[Open full →]` button re-appears | new this phase |

## Visual Acceptance Criteria

For Phase 53 to pass `gsd-ui-checker`:

1. **Patients list focus ring visible** — `Tab` to a row in `/patients`; row shows `2px solid var(--accent-ring)` outline with `-1px` offset (visually indistinguishable from Phase 52 Explorer ring).
2. **`J` on focused patient row opens drawer** — drawer title shows `Patient/{id}` in IBM Plex Mono; body shows `JsonViewer` (full JSON tree); `[Open full →]` button visible.
3. **`J` while a filter input is focused does nothing** — drawer does not open; no toast.
4. **`J` with no focused row does nothing** — drawer does not open; no toast.
5. **Cmd+click on resolved reference chip opens drawer** — drawer title shows `{type}/{id}` in mono; body shows full JSON of the *referenced* resource (not the parent resource).
6. **Cmd+click on failed reference chip opens error drawer** — drawer title shows the raw reference string (e.g. `Patient/abc-123`) in IBM Plex Mono; body shows `Reference unresolvable` in `c="dimmed"` (NOT red, NOT a banner, NOT an icon — just dimmed text); `[Open full →]` button is **hidden**.
7. **Plain click on reference chip is unchanged** — no drawer; existing in-app navigation works exactly as before.
8. **Cmd+click on `RelatedResourcesPanel` Card opens drawer with first matching resource** — drawer body shows that resource's JSON; no toast; no spinner appeared on the Card during the fetch.
9. **Cmd+click on `RelatedResourcesPanel` Card when fetch returns empty / errors** — drawer opens in error state; title shows `{Type}?{param}={refValue}` in mono; body shows `Reference unresolvable` dimmed.
10. **Plain click on `RelatedResourcesPanel` Card is unchanged** — navigates to filtered explorer view (no drawer).
11. **Esc closes drawer in error state** — focus returns to originating element (the reference chip / card / patient row that triggered the error open).
12. **Enter while error drawer is open does nothing** — no navigation, no toast (no resource to open).
13. **Drawer dimensions unchanged** — error state drawer is still 420px wide, right-positioned, no overlay (Phase 52 contract preserved).
14. **Mono title in error state** — title text uses IBM Plex Mono (not IBM Plex Sans) — visually consistent with success-state title.
15. **Zero toasts emitted** across all Phase 53 surfaces; full Phase 53 walk emits zero `notifications.show(...)` calls.
16. **No new accent colors** — only the patient row focus ring is a net-new accent application; `ReferenceLink` Anchor and `RelatedResourcesPanel` Card visual styling is byte-identical pre/post Phase 53.
