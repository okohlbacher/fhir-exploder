<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| FHIR data → React state (PeekContext) | The `reference` string passed to `openPeekError(...)` originates from FHIR Reference.reference fields fetched from the Blaze server; treated as untrusted text but never executed. |
| PeekState.referenceText → DOM (drawer title) | The user-visible title in the drawer renders the raw reference string via Mantine `<Text>`, which escapes HTML by default — no `dangerouslySetInnerHTML` involved. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Spoofing | `JsonPeekDrawer` drawer title (referenceText path) | mitigate | Title is rendered as `<Text size="sm" ff="monospace" fw={600}>{titleText}</Text>` — Mantine `Text` escapes HTML; no `href` is constructed from `referenceText`. Even a malicious reference like `<script>` displays as literal text. |
| T-53-02 | Tampering | `openPeekError` reducer in `PeekProvider` | mitigate | The reducer atomically `setPeekState({ resource: null, ...})` — there is no partial state where `resource` could be a stale non-null value while `error` is set. Test #1 in Task 2 asserts `resource === null` immediately after `openPeekError` runs, locking the contract. |
| T-53-03 | Information Disclosure | Error body `<Text c="dimmed">Reference unresolvable</Text>` | accept | The literal string contains no FHIR data. The drawer's referenceText title surfaces the user-known FHIR reference (e.g. `Patient/abc`) — no PII beyond what was already on the page that triggered the click. Local-only Blaze tool with no remote sink for these strings. |
| T-53-04 | Denial of Service | Drawer Enter shortcut in error state | mitigate | The Enter handler early-returns when `isError === true` (Task 3 explicit guard). Without this, a malicious reference click could trigger navigation to `/explorer/{type}/{id}?mode=json` for a non-existent ID — which would render an empty resource page rather than a true DoS, but the no-op contract is cleaner UX. |
</threat_model>
