# Phase 19 — UI Design Contract

> Visual and interaction contract for the Quality Trends & PDF Reports phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 19 extends the Phase 18 quality-alerting dashboard with two new capabilities:

1. **Trends tab** — a 9th tab on `/quality` labeled "Trends" that visualizes up to 7 quality metrics across captured snapshots. Default view is a small-multiples grid of 7 mini line charts (one per metric) with per-snapshot threshold overlays and per-point breach coloring; an "Overlay all metrics" toggle collapses the grid into a single 7-series line chart for cross-metric comparison.
2. **PDF export** — an "Export PDF" toolbar button on `/quality` that generates a deterministic, multi-page Letter-size PDF report (Header / Overview / Trends / Footer) via off-screen DOM composition + `html-to-image` + `jsPDF`.

Two new `/quality` toolbar buttons are introduced ("Capture snapshot", "Export PDF") and one `/quality` tab is appended ("Trends"). The phase adds **no new design tokens, no new fonts, and no theme changes**. All new surfaces reuse Mantine 8 primitives (`Tabs`, `Button`, `Modal`, `SimpleGrid`, `Card`, `Center`, `Alert`, `Switch`, `Badge`, `Text`, `Title`, `Paper`), `@mantine/charts` 8.3.18 (`LineChart`, `ChartTooltip`), `@mantine/notifications` (`notifications.show`), `@tabler/icons-react` 3.41.1 icons, and the Phase 18 breach-color semantics (`red.6` breach / `blue.6` ok / `gray.5` disabled).

**Dependency actions owned by this phase (tracked elsewhere, repeated here for traceability):**

| Action | Purpose |
|--------|---------|
| `npm install @mantine/charts@8.3.18` (downgrade from 9.0.1) | Align peer deps with React 18 + Mantine 8; silences `npm ls` "invalid" warning. |
| `npm install jspdf@^4.2.1` | New dependency for client-side PDF assembly. MIT, ESM, no React peer. |

## Spacing Scale

Inherits Mantine default spacing tokens (multiples of 4) from prior phases. Use token names in JSX (`gap="md"`), never hard-coded pixels, **except** inside `PdfReportLayout.tsx` where fixed pixel values are required for deterministic page sizing (see PDF Layout Contract below).

| Token | Value | Usage in Phase 19 |
|-------|-------|-------------------|
| xs | 4px | Gap between chart icon and title in empty state; inner padding inside mini-chart card header |
| sm | 8px | SimpleGrid `spacing="sm"` between mini charts; gap between toolbar buttons on the Trends tab toolbar; gap between toggle label and Switch |
| md | 16px | Default gap between Trends page sections (toolbar, chart grid, soft warning Alert); padding inside mini-chart `Card`; Modal body `gap="md"` |
| lg | 24px | Gap between page-level sections inside `<Stack gap="lg" p="xl">` (inherited from QualityOverviewPage pattern); gap between PDF sections on a single page |
| xl | 32px | Outer page padding (inherited `p="xl"` on `<Stack>`); PDF page edge margin is also 32px (see PDF Layout) |
| 2xl | 48px | PDF portal inner padding (header page top margin, section breathing room) — 48px matches Mantine's `xl` + 16px and gives visual headroom on Letter-size pages |
| 3xl | 64px | Not used |

Exceptions:
- `PdfReportLayout.tsx` uses fixed pixel values only (816×1056 page, 48px padding, 40px header bar, explicit tile widths) because the PDF format requires deterministic geometry that does not respond to browser width. Tokens are NOT used inside the portal.
- Mini-chart card height is fixed at **200px** (card) wrapping a **160px** chart body with a 40px header strip (icon + label). This height is a non-token exception locked by D-07 ("card-sized ~280×160").

## Color

Inherits the Mantine default light-theme 60/30/10 split established Phase 18; no new palette introduced. Phase 19 **extends the Phase 18 breach palette** to a three-state palette for trend data points (breached / ok / disabled).

| Role | Value | Mantine Token | Usage in Phase 19 |
|------|-------|---------------|-------------------|
| Dominant (60%) | `#FFFFFF` | `white` | Page background, tile surfaces, PDF page background, empty-state surface, Alert surface (when `variant="light"`) |
| Secondary (30%) | `#F8F9FA` / `#F1F3F5` | `gray.0` / `gray.1` | Mini-chart card secondary background (`bg="gray.0"` on the header strip inside each mini-card); Alert background (soft warning banner `color="yellow" variant="light"`) |
| Accent (10%) | `#228BE6` | `blue.6` | See reserved-for list below |
| Breach (signal) | `#FA5252` | `red.6` | See reserved-for list below |
| Disabled (data) | `#868E96` | `gray.6` | Threshold reference line `stroke` when rendered; threshold-line label text |
| Neutral (data) | `#ADB5BD` | `gray.5` | Threshold-disabled data points (null threshold at capture); chart grid lines (Mantine default) |
| Warning (soft) | `#FAB005` | `yellow.6` | Soft-warning Alert `color="yellow"` when `snapshots.length > 500` |

**Accent (`blue.6`) reserved for:**
- "Capture snapshot" toolbar button on `/quality` (`variant="light"` + `color="blue"` — same treatment as "Recompute metrics" and "Configure thresholds")
- Primary score-line stroke on mini-charts (`stroke="var(--mantine-color-blue-6)"` on the `'score'` series)
- **Ok**-state data points (`fill="var(--mantine-color-blue-6)"` in `<BreachDot>`)
- Notification "info" color (`color="blue"`) for success toasts
- Focus ring on new interactive elements (Switch focus, Tab focus) — Mantine default
- "Export PDF" toolbar button (`variant="filled"` + `color="blue"` — elevated above the `variant="light"` family because it is the only truly outbound action in the toolbar; see I-01)

**Breach (`red.6`) reserved for:**
- Breached-state data points on mini-charts (`fill="var(--mantine-color-red-6)"` in `<BreachDot>`)
- "Breached" indicator text inside hover tooltips (`c="red.6"` `fw={600}`)
- "Clear history" destructive button inside the confirmation modal (`color="red"`) — same pattern as Phase 18 reset
- NOT applied to overlay-mode series (overlay uses a categorical 7-color palette — see below)

**Disabled (`gray.5`) reserved for:**
- Null-threshold data points on mini-charts (`fill="var(--mantine-color-gray-5)"` in `<BreachDot>`)
- Threshold reference line stroke on mini-charts (`stroke="var(--mantine-color-gray-6)"`)
- "Clear history" toolbar button (`variant="subtle"` + `color="gray"` — destructive but reachable; the RED treatment lives on the confirmation modal button, not the trigger)

**Overlay-mode categorical palette (7 metrics, used ONLY in overlay chart):**

Claude's Discretion locks this to **fresh `@mantine/charts` palette with shade 6** (not the OverviewStrip icon-accent colors) so the 7 lines have uniform saturation and are visually distinguishable. Using the icon-accent colors directly would give some metrics pastel strokes (the icons are at size 18 on light surfaces, not on chart lines).

| Metric | Series stroke | Rationale |
|--------|--------------|-----------|
| Completeness | `blue.6` | `#228BE6` — matches primary brand, most frequently inspected metric |
| Coding coverage | `grape.6` | `#BE4BDB` — distinct from blue on color wheel |
| Validation | `teal.6` | `#12B886` — pairs with `IconShieldCheck` green-tech association |
| Plausibility | `orange.6` | `#FD7E14` — warm caution, echoes "temporal/clinical plausibility" |
| Lab ranges | `cyan.6` | `#15AABF` — lab/clinical cool palette association |
| Duplicates | `pink.6` | `#E64980` — distinct from red (not a breach signal) |
| References | `indigo.6` | `#4C6EF5` — relational / link association |

These 7 shade-6 colors are all from Mantine's default categorical palette and are pre-validated for WCAG contrast against `#FFFFFF`. Colors are NOT role-based — they are categorical identifiers. The breach coloring (red dots) is NOT applied in overlay mode to avoid visual conflict with the 7-color series (see I-04 Overlay Mode).

**Destructive red** is reserved for explicit destructive confirmations only (the "Clear history" modal's confirm button and the breach-state dots on mini-charts). It is NOT used for tab highlights, toasts, or borders.

## Interaction Contracts

### I-01: `/quality` Toolbar Button Ordering & Behavior

**Trigger:** User lands on `/quality` (any tab).

**Layout (locked):** The toolbar's right-hand `<Group gap="sm">` contains exactly 5 elements, in this left-to-right order:

| # | Element | Visual | Copy | onClick |
|---|---------|--------|------|---------|
| 1 | Last-computed timestamp | `<Text size="sm" c="dimmed">` | `Last computed {relative}` | N/A |
| 2 | Configure thresholds button | `variant="light"` `color="blue"` `leftSection={<IconAdjustmentsAlt size={16} />}` | `Configure thresholds` | `navigate('/quality/thresholds')` |
| 3 | Capture snapshot button (NEW) | `variant="light"` `color="blue"` `leftSection={<IconCamera size={16} />}` | `Capture snapshot` | `handleCapture()` — builds QualitySnapshot, `append()`s to trends history, shows notification |
| 4 | Export PDF button (NEW) | `variant="filled"` `color="blue"` `leftSection={<IconFileDownload size={16} />}` `loading={exporting}` | `Export PDF` | `handleExport()` — async, sets `exporting` true → unmounts when complete/errored |
| 5 | Recompute metrics button | `variant="light"` `color="blue"` `leftSection={<IconRefresh size={16} />}` | `Recompute metrics` | existing behavior |

**Ordering rationale:** Group by lifecycle: configure (thresholds) → observe (capture, export) → recompute. Export PDF gets the `filled` variant because it is the only outbound/shareable action and earns the emphasis; all other blue buttons are `light`. This is the ONLY `variant="filled"` button on the toolbar.

**At narrow widths (< 1024px):** The right-hand Group wraps to a second line below the left-hand Group (CohortSelector + SampleSizeControl). Mantine `<Group>`'s default `wrap` behavior handles this. No separate responsive treatment required; the REQUIREMENTS explicitly scope this as a desktop-only tool (1200px+).

**Keyboard:** `Tab` order follows left-to-right visual order. `Enter` / `Space` activates each button.

**Capture button behavior:**

1. Synchronous (no async). On click:
   - Read `overallCompleteness`, `overallCoverage`, `overallValidation`, `overallPlausibility`, `overallLabRanges`, `overallDuplicates`, `overallReferences` from `QualityMetricsContext`.
   - Read active thresholds from `useThresholds().getActiveThreshold(key)` for all 7 metric keys.
   - Read `sampleSize` from `useSampleSize()`.
   - Read `cohort` from the existing `quality.cohort.v1` useLocalStorage.
   - Read `serverUrl` from `client.getBaseUrl()`.
   - Build `QualitySnapshot`, append via `useTrendsHistory().append()`.
2. On success: `notifications.show({ color: 'blue', title: 'Snapshot captured', message: 'Added to trend history.', autoClose: 2500 })`. No modal, no page change.
3. On `QuotaExceededError` from localStorage: `notifications.show({ color: 'red', title: 'Snapshot not saved', message: 'Browser storage is full. Clear history on the Trends tab to make room.', autoClose: 6000 })`.
4. Button is **enabled at all times** — even if `QualityMetricsContext` has undefined values (the snapshot records `null` for those metrics, which is the correct audit behavior: "this metric was not run at capture time").
5. `aria-label="Capture snapshot. Records current quality metrics to trend history."`

**Export PDF button behavior:**

1. Async. On click:
   - Set local `exporting` state to `true` (disables the button and shows Mantine's built-in loading spinner inside the `filled` button).
   - Mount `PdfReportLayout` into an off-screen portal (`position: fixed; top: 0; left: 0; width: 816px; z-index: -1; pointer-events: none; opacity: 0`).
   - `await document.fonts.ready`.
   - `await` double `requestAnimationFrame`.
   - For each `pageRef`, call `toPng(ref.current, { pixelRatio: 2, cacheBust: true, backgroundColor: '#ffffff', width: 816, height: 1056 })`.
   - Build `jsPDF({ orientation: 'portrait', unit: 'px', format: [816, 1056], compress: true, hotfixes: ['px_scaling'] })`.
   - `doc.addImage(png, 'PNG', 0, 0, 816, 1056, undefined, 'FAST')` per page, with `doc.addPage()` between.
   - `doc.save(pdfFilename(serverUrl, new Date()))`.
   - Unmount portal. Set `exporting` to `false`.
2. On success: `notifications.show({ color: 'blue', title: 'Report downloaded', message: 'Your browser saved the PDF to its default downloads folder.', autoClose: 4000 })`.
3. On error (any thrown): `notifications.show({ color: 'red', title: 'Export failed', message: 'Could not generate PDF. See browser console for details.', autoClose: 6000 })` and `console.error(err)`.
4. While `exporting === true`: button shows spinner, is disabled. No full-page `LoadingOverlay` (locked by discretion — the button-internal spinner is sufficient and doesn't block other interactions).
5. `aria-label="Export PDF report of current quality dashboard state."`

**Filename pattern (locked):**

```
fhir-exploder-quality-report_{serverUrlSlug}_{YYYY-MM-DD_HHMMSS}.pdf

where:
  serverUrlSlug  = lowercased, no protocol, no trailing /fhir, path separators → '-', max 60 chars
  YYYY-MM-DD    = UTC date
  HHMMSS        = UTC time, no separators

examples:
  fhir-exploder-quality-report_localhost-8080_2026-04-14_183042.pdf
  fhir-exploder-quality-report_blaze-mii-example-org_2026-04-14_183042.pdf
```

**`<BreachDot>` contract (locked per D-12):**

| `payload.threshold` value | `payload.score` below threshold? | Dot fill | Radius |
|--------------------------|----------------------------------|----------|--------|

### I-07: Include-Other-Servers Filter

**Trigger:** User toggles "Include other servers" Switch.

**Behavior:**

1. Default = **off**: `TrendsPanel` filters `snapshots` to only those matching `currentServerUrl`.
2. On: all snapshots render regardless of `serverUrl`.
3. **Visual disambiguation between servers** (accessibility + colorblind-safety):
   - Per-server **dot shape** varies: current server = filled circle (Mantine/recharts default), each other server = outlined square / triangle / diamond in rotation. (Uses recharts `<Line dot={customShape}>` with shape keyed on `serverUrl`.)
   - Per-server **stroke dash pattern** does NOT vary (all lines are solid) — dash variations conflict with the threshold dashed line.
   - Tooltip adds a line: `Server: {serverUrlSlug}` when `Include other servers = on`.
   - Legend in overlay mode adds the slug after the metric name: `Completeness (localhost-8080)` — only when `Include other servers = on` and multiple servers are present.
4. When only one `serverUrl` exists in storage, the switch is disabled with `aria-label="Include snapshots from other servers (no other servers in history)"`.

**Accessibility:** Color alone is never the sole signal for server identity — shape variation is the primary channel, with tooltip text as a screen-reader-accessible fallback.

## Accessibility Contract

### Color-Not-Alone for Breach Signals

**Breach state on mini-chart dots uses BOTH color AND text:**

- Color: `red.6` dot fill — primary signal for sighted users.
- Text in tooltip: `Breached` in `c="red.6"` `fw={600}` — readable by screen readers + not-colorblind-dependent users.
- Text in tooltip: `Score: 72%` AND `Threshold: 80%` — numerically self-describing (72 < 80 is visible in the numbers, independent of color).

**Disabled-threshold state uses BOTH color AND text:**

- Color: `gray.5` dot fill.
- Tooltip line: `Threshold: disabled`.

**Accessibility rationale for colorblind users:**

- Red vs blue vs gray dot fills are distinguishable in deuteranopia / protanopia / tritanopia simulations (validated against WCAG ANDI color-contrast rules: red.6 and blue.6 differ in luminance by >2:1; gray.5 is low-saturation and pale).
- Even if color is fully imperceptible, every breach has a textual `Threshold: N%` annotation in the tooltip AND the numerical gap (`Score: 72%` vs `Threshold: 80%`) is self-evident.

### Keyboard Navigation

| Target | Reached via | Activated via |
|--------|-------------|--------------|
| Capture snapshot button | `Tab` from toolbar | `Enter` / `Space` |
| Export PDF button | `Tab` | `Enter` / `Space` |
| Trends tab | `Arrow Right` within Tabs.List | `Arrow` keys or `Enter` (Mantine default) |
| Clear history button (in Trends panel) | `Tab` | `Enter` / `Space` |
| Overlay switch | `Tab` | `Space` (toggle) |
| Include-other-servers switch | `Tab` | `Space` |
| Clear history confirm button (in modal) | `Tab` from modal (after auto-focus on dismiss) | `Enter` / `Space` |
| `Esc` | anywhere in modal | Closes modal (dismiss) |

**Chart interaction:** `@mantine/charts` / recharts tooltips are mouse-hover by default and do NOT have built-in keyboard equivalents. For Phase 19 this is an accepted constraint (the PDF provides a screen-reader-accessible alternative via text: the Trends section in PDF output includes the summary line `{N} snapshots between {date1} and {date2}`, and per-snapshot values could be added in a future enhancement as a data table; deferred for now).

**Screen-reader chart summary:** To partially mitigate the tooltip-only data access, each `TrendMiniChart` renders an invisible-but-screen-reader-visible summary:

```typescript
<VisuallyHidden>
  <p>
    {METRIC_LABELS[metric]} across {snapshots.length} snapshots. Latest value: {latestScore ?? 'no data'}%.
    {breachedCount > 0 && ` ${breachedCount} snapshot(s) below threshold.`}
  </p>
</VisuallyHidden>
```

`VisuallyHidden` is from `@mantine/core`. This is a chart-data summary for screen readers, NOT a caption visible to sighted users. Added per WCAG 1.1.1 (non-text content) minimum requirement.

### ARIA Labels

All icon-only buttons have `aria-label`:

- `<ActionIcon>` for the (nonexistent in this phase — no icon-only controls introduced).
- Switch labels ARE the visual label; `aria-label` duplicates for redundancy only where the copy varies by state (see Copywriting table).

All buttons with text + icon do NOT need `aria-label` (Mantine's Button forwards text content as accessible name). The Capture and Export buttons DO have `aria-label` for richer context (see Copywriting) — overrides the default to give screen-reader users the full action context.

### Focus Visible

All new interactive elements inherit Mantine's default focus outline (2px `blue.6`, `outline-offset: 2px`). No focus-outline overrides. Tested against WCAG 2.4.7 focus-visible requirement.

### Modal Focus Trap

`ClearHistoryModal` uses Mantine `Modal` default focus-trap behavior:
- On open: focus moves to the first focusable element inside (the "Keep history" dismiss button).
- `Tab` cycles within modal only.
- `Shift+Tab` reverse cycles.
- `Esc` closes modal and returns focus to the "Clear history" button that opened it.

### Contrast

All new text / icon pairs meet WCAG AA:

- Mini-chart `metric label` text (`gray.9` on `gray.0` header strip) = 14.5:1 (AAA).
- Mini-chart threshold line (`gray.6` on `white`) = 4.6:1 (AA).
- Mini-chart ok-state dot (`blue.6` on `white`) = 4.8:1 (AA).
- Mini-chart breach-state dot (`red.6` on `white`) = 4.5:1 (AA).
- Overlay-mode series colors (all shade-6 categorical) — pre-validated by Mantine's default palette.
- PDF footer text (`gray.6` on `white`) = 4.6:1 (AA).

### PDF Accessibility (structural)

PDF output is an image-based export (PNG pages → jsPDF). It is NOT a tagged / screen-reader-navigable PDF in v1. The PDF is intended as a shareable visual audit artifact. For screen-reader access to trend data, users should inspect the live `/quality` page. A future enhancement to emit a parallel text transcript (`.txt`) alongside the PDF is captured in Deferred (CONTEXT.md) and NOT in scope for Phase 19.
