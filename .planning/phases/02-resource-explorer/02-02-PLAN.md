<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User filter input -> FHIR search URL | TextInput values from filter panel become search parameters |
| FHIR server response -> SearchControl rendering | Server-returned Bundle rendered in table |
| URL params -> application state | Browser URL drives search state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | SearchFilterPanel input -> SearchRequest | mitigate | Filter values pass through Medplum's formatSearchQuery which encodes parameters safely. Never concatenate raw user input into URLs. |
| T-02-05 | Tampering | URL params manipulation | mitigate | parseSearchRequest from @medplum/core validates and sanitizes URL params into structured SearchRequest. Invalid params produce empty/safe results. |
| T-02-06 | Denial of Service | Pagination _count parameter | mitigate | Page size selector limits to fixed options [10,25,50,100]. Direct URL manipulation with large _count handled server-side by Blaze. |
| T-02-07 | Information Disclosure | SearchControl renders server data | accept | Read-only app by design; user already has server access. No additional exposure. |
</threat_model>
