## Spacing Scale

Declared values use Mantine's default spacing scale (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge spacing |
| sm | 8px | Compact element spacing, table cell padding |
| md | 16px | Default element spacing, card padding, sidebar section padding |
| lg | 24px | Section gaps between major UI blocks (Stack gap="lg" pattern from Phase 1) |
| xl | 32px | Page-level vertical padding, large section breaks |
| 2xl | 48px | Empty state vertical padding |
| 3xl | 64px | Not used in this phase |

Exceptions: none

## Typography

Uses Mantine size tokens mapped to the system font stack. Phase 1 established these patterns:

| Role | Size | Weight | Line Height | Mantine Token |
|------|------|--------|-------------|---------------|
| Body | 14px | 400 (regular) | 1.55 | sm |
| Label | 14px | 500 (medium) | 1.55 | sm, fw={500} |
| Heading | 20px | 600 (semibold) | 1.2 | Title order={2} |
| Subheading | 16px | 600 (semibold) | 1.3 | Title order={4} |

Usage in this phase:
- **Body (sm, 400):** Search result cell text, JSON content, resource property values
- **Label (sm, 500):** Resource type names in links, search parameter labels, tab labels, breadcrumb segments
- **Heading (order=2, 600):** Page title ("Resource Explorer"), resource detail heading
- **Subheading (order=4, 600):** Section headings within resource detail (e.g., "Search Parameters", display mode labels in clinical+raw view)

## Color

Follows Mantine default light theme with blue primary, established in Phase 1:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff (white) | Page background, main content area, JSON viewer background |
| Secondary (30%) | #f8f9fa (gray.0) | Sidebar, search filter panel background, table header row, Card surfaces |
| Accent (10%) | #228be6 (blue.6) | See reserved list below |
| Destructive | #fa5252 (red.6) | Error badges, connection error indicators only |

Accent reserved for:
- Resource type links (clickable resource names in search results)
- Reference field links (clickable FHIR references via ReferenceDisplay)
- Active display mode tab indicator
- Primary "Search" button
- Active breadcrumb segment
- Resource count badges (Badge color="blue" variant="light", established in Phase 1)
- Page size selector active state

Semantic colors also in use (from Phase 1 patterns):
- **orange** (warning): Advanced filter toggle hint, _include/_revinclude info callout
- **green** (success): Connection status dot (inherited from sidebar)
- **gray/dimmed** (neutral): Metadata text, secondary counts, disabled states

## Interaction Contracts

### Search Flow (D-01, D-02, D-03, D-04)
1. User arrives at `/explorer/:resourceType` (via dashboard link or type selector)
2. Curated search params shown by default (name, date, status, code depending on type)
3. User fills params, clicks "Search" or presses Enter
4. URL updates with search state: `/explorer/Patient?name=Mueller&_count=25`
5. Results load with Skeleton placeholders, then render in SearchControl table
6. Browser back/forward navigates search history

### Pagination Flow (D-07, D-08, D-09)
1. Results show "Showing 1-20 of 1,234" (or "Showing 1-20" if Bundle.total unavailable)
2. "Next" button enabled when bundle.link contains rel=next
3. "Previous" button enabled when bundle.link contains rel=prev
4. Page size dropdown changes _count param, resets to first page
5. Both Next/Previous buttons disabled during loading

### Display Mode Switching (D-10)
1. Resource detail view defaults to "Human-readable" tab
2. Tabs: "Human-readable" | "Clinical + Raw" | "Developer"
3. Switching tabs preserves scroll position within the resource
4. Clinical+Raw view: 50/50 split, left panel scrolls independently from right panel
5. Developer/JSON view: monospace font, syntax-highlighted, line numbers optional

### Reference Navigation (D-11, D-12)
1. Reference fields render as blue underlined links (via ReferenceDisplay)
2. Clicking a reference navigates to `/explorer/{referencedType}/{referencedId}`
3. Breadcrumb trail updates: each segment is a clickable link back to that resource
4. Breadcrumb format: `ResourceType/id` per segment, e.g., "Patient/123 > Encounter/456 > Condition/789"
5. Clicking a breadcrumb segment navigates back to that resource (intermediate segments remain)

### Include/Revinclude (D-13)
1. _include and _revinclude appear in the advanced filter panel (behind "Show all filters")
2. Presented as multi-select fields listing available include paths from CapabilityStatement
3. Included resources appear in search results table with a visual grouping indicator (indented row or subtle background color difference)

## States Matrix

| State | Visual Treatment |
|-------|------------------|
| Loading search results | Skeleton rows (3-5 rows of Skeleton height=36) in table area |
| Loading resource detail | Skeleton blocks for heading + content area |
| Loading resource counts | Loader size="xs" inline (established Phase 1 pattern) |
| Search results empty (no filters) | Centered empty state with body text and no icon |
| Search results empty (with filters) | Centered empty state with body text suggesting filter adjustment |
| Search error | Alert color="red" with error message and "Retry" button |
| Resource not found | Alert color="red" with "Resource not found" message and back link |
| Reference target missing | ReferenceDisplay shows reference string as plain text (not clickable) if resolution fails |
| Pagination at start | "Previous" button disabled (variant="default", disabled) |
| Pagination at end | "Next" button disabled |
| Bundle.total unavailable | Omit total from "Showing X-Y" text; hide if position cannot be determined |
| Server disconnected | Redirect to dashboard with connection error (reuse Phase 1 error handling) |

## JSON Syntax Highlighting

For the Developer/JSON display mode (D-10.3, BRWS-04):

| Token Type | Color |
|------------|-------|
| String values | #2f9e44 (green.7) |
| Number values | #e8590c (orange.8) |
| Boolean / null | #9c36b5 (grape.7) |
| Property keys | #1971c2 (blue.7) |
| Brackets / braces | #495057 (gray.7) |
| Background | #f8f9fa (gray.0) |

Font: `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace` at 13px, line-height 1.5.

Implement as a lightweight custom component (no external syntax highlighting library needed for JSON-only highlighting). Use `<pre>` with `<span>` color tokens.
