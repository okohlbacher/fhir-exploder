# Phase 15 — UI Design Contract

> Visual and interaction contract for the Quality Check Engine & Drill-Down phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 15 adds per-resource drill-down capability to the three existing quality panels (completeness, coding coverage, validation). The primary new UI element is a shared `ResourceIssueTable` component rendered inside a Mantine `Tabs` layout on each drill-down page. A "Fields" tab preserves the existing field-level view; a new "Resources" tab lists specific resources with issues, each linking to the resource detail view. Cross-filtering from a field row to the Resources tab is the key interaction pattern. No new colors, no new type sizes, no new dependencies.

## Interaction Contracts

### I-01: Tab Navigation (Fields / Resources)

**Trigger:** User navigates to any drill-down page (coding, completeness, or validation).

**Default state:** "Fields" tab is active, showing the existing field-level breakdown.

**Behavior:**
1. Mantine `Tabs` with controlled `value`/`onChange` state, defaulting to `"fields"`.
2. Two tabs: "Fields" (existing content) and "Resources" (new `ResourceIssueTable`).
3. Tab switching is instant (no network requests) -- both tabs render from the same hook data.
4. Tab state resets when navigating to a different resource type's drill-down.

**Mantine API:** `<Tabs value={activeTab} onChange={setActiveTab}>` with `<Tabs.List>`, `<Tabs.Tab>`, `<Tabs.Panel>`.

### I-02: Cross-Filter from Fields to Resources

**Trigger:** User clicks a field row in the Fields tab.

**Behavior:**
1. Clicking a field path row (e.g., `code.coding[*]`) sets the field filter to that path and switches to the "Resources" tab in a single state update.
2. The Resources tab opens with the field filter pre-populated, showing only issues for that specific field.
3. The field filter is a `TextInput` that the user can manually clear or modify.
4. Clearing the field filter shows all issues again.

**Visual cue for clickable rows:** Field path rows in the Fields tab use `cursor: pointer` and show a subtle hover background (Mantine `highlightOnHover` on Table, or explicit hover style on the row). The field path text renders in `blue.6` when the Resources tab has issues for that field, indicating it is actionable.

**State flow:**
```
handleFieldClick(path) -> setFieldFilter(path) + setActiveTab('resources')
```

### I-03: Severity Filter

**Trigger:** User selects a value from the severity dropdown on the Resources tab.

**Behavior:**
1. `Select` component with options: "All severities", "error", "warning", "info".
2. Default: "All severities" (no filtering).
3. Changing the filter resets pagination to page 1.
4. Filter is applied client-side to the `NormalizedIssue[]` array before pagination.

**Mantine API:** `<Select data={['All severities', 'error', 'warning', 'info']} value={severityFilter} onChange={setSeverityFilter} />` with `size="sm"` and `w={180}`.

### I-04: Field Path Filter

**Trigger:** User types in the field path filter `TextInput`, or it is pre-populated via cross-filter (I-02).

**Behavior:**
1. `TextInput` with placeholder "Filter by field path...".
2. Filters issues where `issue.field` contains the filter string (case-insensitive substring match).
3. Changing the filter resets pagination to page 1.
4. When pre-populated via cross-filter, the input shows the exact field path. User can modify or clear it.

**Mantine API:** `<TextInput placeholder="Filter by field path..." value={fieldFilter} onChange={(e) => setFieldFilter(e.currentTarget.value)} />` with `size="sm"` and `style={{ flex: 1 }}`.

### I-05: Client-Side Pagination

**Trigger:** User clicks a page number in the pagination control.

**Behavior:**
1. 50 items per page (D-06).
2. Mantine `Pagination` component at the bottom of the table.
3. A text label above the table: "Showing {start}--{end} of {total} issues" at `size="sm"` `c="dimmed"`.
4. Pagination resets to page 1 when any filter changes.
5. If filtered results fit in one page, pagination is hidden.

**Mantine API:** `<Pagination total={totalPages} value={page} onChange={setPage} />` with `size="sm"`.

### I-06: Resource Detail Navigation

**Trigger:** User clicks a resource ID in the ResourceIssueTable.

**Behavior:**
1. Resource ID column renders as `<Anchor component={Link} to={/explorer/${type}/${id}} c="blue.6" size="sm">` -- identical to existing `ValidationIssueList` pattern.
2. Navigates to the Phase 2 resource detail view.
3. Browser back button returns to the drill-down page with tab and filter state preserved (React state persists in the component tree since the drill-down page is not unmounted by the router).

## Layout Contract

### ResourceIssueTable Internal Layout

```
+----------------------------------------------------------+
| [Severity dropdown]  [Field path filter...............]  |  <- Group gap="sm"
| Showing 1-50 of 234 issues                               |  <- Text size="sm" c="dimmed"
+----------------------------------------------------------+
| #  | Severity | Resource        | Field      | Description |  <- Table.Thead sticky
|----|----------|-----------------|------------|-------------|
| 1  | [error]  | Patient/abc123  | code       | Missing ... |  <- Table.Tr
| 2  | [warn]   | Patient/def456  | code[*]    | Text-only   |
| .. | ...      | ...             | ...        | ...         |
+----------------------------------------------------------+
|            < 1  2  3  4  5 >                              |  <- Pagination
+----------------------------------------------------------+
```

- Table uses `striped highlightOnHover stickyHeader` (matching ValidationIssueList).
- Table container has `maxHeight: 600` with `overflow: auto` (matching ValidationIssueList).
- Filter bar is a `Group` with `gap="sm"` and `mb="sm"`.
- Pagination is centered below the table with `mt="sm"`.

### Tab Layout (per drill-down page)

```
+----------------------------------------------------------+
| [<- Back to {Panel}]                                      |  <- Button variant="subtle"
| {Type} -- {Panel} breakdown                               |  <- Title order={2}
+----------------------------------------------------------+
| [Fields]  [Resources]                                     |  <- Tabs.List
+----------------------------------------------------------+
| {Tab content: existing field view OR ResourceIssueTable}  |  <- Tabs.Panel
+----------------------------------------------------------+
```

- Outer `Stack gap="md" p="xl"` preserved from existing drill-down pages.
- `Tabs` sits after the title, before the content area.
- Tab panels have no additional padding (content padding handled by inner components).

## Empty & Error States

### Empty State: No Issues

**When:** The walker returns zero issues for the Resources tab (all sampled resources are clean).

**Render:** Mantine `Alert` with `color="green"` `variant="light"`.
- Icon: `IconCheck` from `@tabler/icons-react`.
- Title: "No issues found"
- Body: "All sampled resources passed this quality check. Increase the sample size to check more resources."

### Empty State: Filters Yield Nothing

**When:** Issues exist but current severity + field filters exclude all of them.

**Render:** Mantine `Text` with `c="dimmed"` `size="sm"` `ta="center"` inside the table area.
- Copy: "No matching issues. Clear filters to see all issues."
- No icon needed -- this is a transient filter state, not a permanent empty state.

### Error State: Walker Failure

**When:** The quality hook returns `'error'` state (network failure, FHIR server timeout).

**Render:** Mantine `Alert` with `color="red"` `variant="light"` (existing pattern from CodingDrillDown / CompletenessDrillDown).
- Copy: "Failed to load per-resource data for {type}. Return to the quality dashboard and try again."
- No retry button -- user navigates back via the existing back button.

### Loading State

**When:** Quality hook is in `'loading'` state.

**Render:** 4 Mantine `Skeleton` rows at `height={24}` `radius="sm"` (existing pattern from CodingDrillDown / CompletenessDrillDown). Shown in whichever tab is active.

## Accessibility Notes

- Mantine `Tabs` provides ARIA `role="tablist"`, `role="tab"`, `role="tabpanel"` and keyboard navigation (arrow keys between tabs, Enter/Space to activate) out of the box.
- Table uses `stickyHeader` for scroll context -- column headers remain visible during vertical scroll.
- Resource ID links use `<Anchor component={Link}>` which renders semantic `<a>` elements, keyboard-focusable by default.
- Filter controls are standard Mantine `Select` and `TextInput` with built-in label/aria support. Use `aria-label` prop if no visible label is rendered.
- Cross-filter click targets (field rows in Fields tab) must have `cursor: pointer` and `role="button"` or be wrapped in a `<button>` for keyboard accessibility.
