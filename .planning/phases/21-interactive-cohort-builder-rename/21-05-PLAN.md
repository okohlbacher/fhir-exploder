<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Textarea paste → parsePatientRefs | Untrusted paste crosses into in-memory state; normalized by Plan 21-01's cap + split regex |
| User text inputs (name, code system, code) → localStorage | Strings stored in browser-local; never sent to external services |
| Cohort name → notification toast / saved list row | Displayed via React text nodes (auto-escaped) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering (XSS via cohort name / paste) | Name TextInput, paste into Textarea | mitigate | All values rendered via React text nodes — no `dangerouslySetInnerHTML`. Mantine components auto-escape. No `eval`/`new Function` anywhere in the form. `parsePatientRefs` normalizes to token-safe strings. |
| T-21-02 | DoS (Textarea paste overflow) | Reference-list Textarea | mitigate | `maxLength={1_048_576}` caps raw input at 1MB (~10k IDs × 100 chars avg is 1MB). `parsePatientRefs` caps parsed to 10k. Debounce (150ms) prevents re-parse on every keystroke for large pastes. |
| T-21-06 | DoS (localStorage quota) | addCohort write path | mitigate | `useCohorts` (Plan 21-02) catches QuotaExceededError and surfaces red toast; the form's save handler wraps in try/catch and shows the same toast. |
| T-21-14 | Injection (duplicate name bypass) | Name uniqueness check | mitigate | Client-side `existingNames.includes(name.trim())` check runs before `addCohort`. Since only the local user can write to their localStorage, bypass is not a security concern — just a UX one. |
| T-21-03 | Information disclosure (PHI in UI) | Saved cohort row metadata | accept | Metadata summary shows criterion types + patient-ref count, never individual patient IDs. Toast messages never include patient lists. Verified by UI-SPEC §S2 row metadata copy. |
</threat_model>
