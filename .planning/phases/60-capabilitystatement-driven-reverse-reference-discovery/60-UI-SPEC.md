# Phase 60 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note (read first)

**This is a data-source-swap phase, not a visual phase.** Phase 60 replaces the static
`reverseReferenceCatalog.ts` import behind `IncomingReferencesPanel` with a dynamic catalog
derived from the connected server's `CapabilityStatement` (CONTEXT D-01..D-09). It introduces:

- **No new components** — `IncomingReferencesPanel.tsx` is modified; `RelatedResourcesPanel.tsx`
  (the actual renderer) is untouched.
- **No new layouts** — same `SimpleGrid cols={{ base: 2, sm: 3, md: 4 }}` card grid.
- **No new visual patterns, tokens, colors, type sizes, or copy.**

The visual output of the "Referenced By" panel **must be pixel-identical** to its current
state. This contract therefore mostly declares invariants — what must NOT change — plus the
three behavioral guarantees the data swap must preserve. All token tables below restate the
**already-established** Mantine 8 + tokens.css design system for checker/auditor reference;
they are not new decisions for this phase.

## Spacing Scale

Restated from the established Mantine theme + tokens.css. **No new spacing introduced in Phase 60.**
`RelatedResourcesPanel` uses Mantine spacing tokens (`mb="sm"`, `gap="xs"`, `padding="sm"`) which
map to the 4px base scale below.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside card (`Group gap="xs"`) |
| sm | 8px | Title bottom margin (`Title mb="sm"`), card padding (`padding="sm"`) |
| md | 16px | Default Mantine element spacing, table horizontal spacing |
| lg | 24px | Card defaultProps padding (theme `Card.padding='lg'`), section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: none. Phase 60 adds zero spacing declarations.

## Typography

Restated from tokens.css + Mantine theme. **No new type sizes/weights introduced in Phase 60.**
The panel uses Mantine `Text size="sm"` (≈14px) and `Title order={5}`. Exactly two weights:
400 (regular) for body, and 600 (semibold) for labels and headings. The resource-type label
is rendered at `fw={600}` — there is no intermediate 500 weight in this contract.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.45 (tokens.css body) |
| Label (card type) | 14px | 600 | 1.45 |
| Heading (panel Title order=5) | 16px | 600 | 1.2 |
| Uppercase micro-label | 11px | 600 | 1.2 |

Weights declared: 400 (regular), 600 (semibold). Exactly two weights — no others for this phase.

## Color

Restated from tokens.css. **No new colors introduced in Phase 60.** The count badge uses the
existing `Badge variant="light" color="blue"` — unchanged. There is no destructive action in
this phase (read-only explorer).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` oklch(99% 0.004 85) | App background, surfaces |
| Secondary (30%) | `--panel` #ffffff / `--panel-2` | Cards, panel inset, table headers |
| Accent (10%) | `--accent` oklch(54% 0.17 262) (indigo) | Count badge (light blue variant), focus rings, primary buttons |
| Destructive | `--bad` oklch(58% 0.16 22) | Not used in Phase 60 (no destructive actions) |

Accent reserved for: count Badge on populated cards, card hover/focus affordance, and the
indigo primaryColor inherited from theme. NOT applied to card body text or labels.

## Copywriting Contract

The only user-visible string this panel renders is the locked title **"Referenced By"**
(CONTEXT D-06 / inline doc in `IncomingReferencesPanel.tsx` line 14). There is no CTA, no
empty-state text, and **no error-state text** in this phase — the fallback path is silent
by design (CONTEXT D-08).

| Element | Copy |
|---------|------|
| Primary CTA | none (panel cards navigate on click; no labeled CTA button) |
| Panel heading | `Referenced By` (locked — do not change) |
| Empty state heading | none rendered — panel returns `null` when no populated entries (existing `RelatedResourcesPanel` behavior, line 116) |
| Empty state body | none — silent absence, no placeholder |
| Error state | none — CapabilityStatement-unavailable fallback is TRANSPARENT (CONTEXT D-08: "No error toast or banner"). Falls through to curated catalog with zero user-visible signal. |
| Destructive confirmation | not applicable (read-only explorer, no destructive actions) |

## Behavioral Invariants (the actual Phase 60 contract)

These are the visual/interaction guarantees the data-source swap MUST preserve. The checker
and auditor validate the implementation against these, not against new pixels.

| # | Invariant | Source |
|---|-----------|--------|
| INV-1 | Panel appearance is **identical** to pre-Phase-60: same `SimpleGrid cols={{ base: 2, sm: 3, md: 4 }}`, same Card anatomy (icon glyph + `fw={600}` type label + light-blue count Badge), same `Title order={5}` "Referenced By". | RelatedResourcesPanel.tsx (unchanged) |
| INV-2 | **No loading spinner regression** — the existing in-flight skeleton (per-card `Loader size="xs"` while counts resolve) stays; catalog *construction* adds no new spinner. `buildDynamicCatalog` runs synchronously inside `connect()` (CONTEXT D-01), so the catalog is already in state before the panel mounts — there is no async catalog fetch to spin on. | CONTEXT D-01 |
| INV-3 | **Fallback is invisible** — when CapabilityStatement is unavailable, or a resource type has no dynamic entries, the panel silently uses the curated catalog. No toast, banner, badge, or copy difference distinguishes dynamic vs fallback rendering. (CONTEXT D-08, D-09; per-type fallback.) | CONTEXT D-08/D-09 |
| INV-4 | **Merge/dedup does not alter visual output** — union of dynamic + curated, deduped by `entryKey = \`${type}:${param}\`` (CONTEXT D-07, matching RelatedResourcesPanel line 23). Card render order and count behavior must remain stable; only the *set* of cards may grow on rich CapabilityStatements (success criterion 2: extra Encounter reference types appear as additional cards). | CONTEXT D-07 |
| INV-5 | **Icon handling for dynamic-only entries:** dynamic entries discovered from CapabilityStatement have no emoji `icon` (icon is optional in `ReverseReferenceEntry`). The existing renderer already guards `{e.icon && <Text size="sm">{e.icon}</Text>}` (RelatedResourcesPanel line 144) — a missing icon renders the label with no leading glyph and NO layout shift. Do not invent placeholder icons for dynamic entries (CONTEXT Deferred: "Icons for dynamic entries"). Curated entries retain their emoji when present in either catalog. | CONTEXT Deferred + RelatedResourcesPanel line 144 |
| INV-6 | **Per-server invalidation is transparent** — on server switch, the disconnect/reconnect flow clears `dynamicCatalog` and the next `connect()` rebuilds it (CONTEXT D-01). No catalog-refresh UI is shown. | CONTEXT D-01 |
