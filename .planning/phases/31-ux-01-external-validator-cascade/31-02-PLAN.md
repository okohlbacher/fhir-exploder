<objective>
Close the two PARTIAL gaps in Phase 31 VERIFICATION.md (Truth #1 and Truth #4), both rooted in CR-01 from 31-REVIEW.md: the PHI acknowledgement UI in `ValidationPanel` writes localStorage under a key derived from the **server-tier** `validation.validatorUrl`, but `cascadingValidator.tryExternal` reads the gate under a key derived from the **external-tier** `validation.externalValidator.url`. In production these keys never agree — the external tier is unreachable from the UI in every realistic deployment. Unit tests do not catch this because they seed localStorage directly at the correct external-tier key, bypassing the UI.

This plan delivers two fixes:
1. **Key alignment + banner visibility extension** — `ValidationPanel.tsx` computes the PHI ack key from `externalValidator.url` when the external tier is configured (falling back to `validatorUrl` otherwise), and the banner Alert renders when EITHER tier is configured.
2. **Integration test** — new `ValidationPanel.phi-gate.integration.test.tsx` renders `ValidationPanel` with external-tier config, clicks "I acknowledge", triggers a cascade run, and asserts `global.fetch` is called with the external validator URL. Locks the UI↔cascade key agreement at the integration level.
