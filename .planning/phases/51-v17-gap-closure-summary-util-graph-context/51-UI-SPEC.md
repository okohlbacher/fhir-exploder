# Phase 51 — UI Design Contract

> Visual and interaction contract for the v1.7 gap-closure phase. Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> **Scope guard:** Phase 51 is a **code-quality refactor with navigation correctness fixes**.
> It introduces **ZERO new UI surfaces**, **ZERO new components**, **ZERO new copy strings**,
> **ZERO new design tokens**, and **ZERO new dependencies**. All visual contracts are inherited
> verbatim from the upstream phases (46, 47, 48, 49) — this spec exists to **lock the
> interaction contracts** for the two GAP fixes (GAP-1 timeline summary parity, GAP-2 graph
> patient-context preservation) and to declare the no-visual-regression invariant.

## Phase Intent (why this UI-SPEC is short)

Per ROADMAP §Phase 51 + REQUIREMENTS NAV-02 / GRPH-03 + `.planning/v1.7-MILESTONE-AUDIT.md`
GAP-1 + GAP-2:

| Change | Visible UI delta | Interaction delta |
|--------|------------------|-------------------|
| `PatientTimeline.tsx` — remove inline `extractSummary`, call `summarizeResource(r).primary` | Encounter event labels may shift from `type[0].text` to `class.display` (or vice-versa) when both fields are present — text content only, NO layout / typography / color change | None — same click-to-navigate behavior preserved |
| `timeline-utils.ts` — drop or thin-re-export `extractSummary`; `ClinicalTimeline.tsx` consumes `summarizeResource` directly | Encounter / Procedure event labels may shift identically to PatientTimeline above | None |
| `ResourceGraphNode.tsx:43` — read `patientId` from route params; navigate to `/patients/:patientId/:type/:id` when present | None — same Card, same Tooltip, same accent border | **CHANGED:** clicking a graph node from the patient-scoped graph route (`/patients/:patientId/:type/:id/graph`) now stays inside the patient browser instead of dropping to the generic Explorer |
| `IncomingReferencesPanel` + `PatientRelatedResources` — preserve patient context in card-click hrefs (orchestrator addendum) | None — same card grid, same counts, same icons | **CHANGED:** card click from a patient-scoped detail page now navigates to `/patients/:patientId/:type?{param}={ref}` instead of `/explorer/:type?{param}={ref}` |

The **only** way Phase 51 should be visually distinguishable from Phase 49's post-merge state is:
1. Some Encounter / Procedure timeline labels show different text (per the locked NAV-02 field-priority winner — see §Copywriting Contract below).
2. URL bar after clicking a graph node from a patient-scoped graph route now starts with `/patients/…` instead of `/explorer/…`.

Everything else is **byte-identical to the post-Phase-49 baseline**.

## Copywriting Contract

Phase 51 introduces **zero new copy strings**. The work is text-substitution at three
internal call sites where one summary computation replaces another. The only **observable
copy delta** for users is the field-priority shift in Encounter / Procedure timeline labels
when both `type[0].text` and `class.display` are present.

### Locked field-priority — Encounter (NAV-02 canonical)

Post-Phase-51, Encounter event labels in `PatientTimeline.tsx` and `ClinicalTimeline.tsx`
follow the **canonical `summarizeResource` order**:

> `class.display → type[0].text → type[0].coding[0].display → "Encounter"`

(per the existing `summarizeResource` Encounter handler — Phase 51 does NOT modify this util).

The legacy `extractSummary` order in `timeline-utils.ts:98-105` was:

> `type[0].text → type[0].coding[0].display → class.display → "Encounter"`

These differ when both `class.display` and `type[0].text` are populated. Per ROADMAP §Phase 51
success criterion #1, **`PatientTimeline` aligns with the canonical order**, accepting any
resulting Encounter-label text shift as the locked NAV-02 outcome.

### Locked field-priority — all other resource types (NAV-02 canonical)

| Resource type | Phase 51 source-of-truth (inherited from `summarizeResource`) |
|---------------|---------------------------------------------------------------|
| Condition | `code.text → code.coding[0].display → code.coding[0].code → "Condition"` |
| Procedure | `code.text → code.coding[0].display → "Procedure"` |
| Observation | `code.text → code.coding[0].display → "Observation"` |
| MedicationStatement | (per `summarizeResource` MedicationStatement handler — preserved verbatim) |
| AllergyIntolerance | (per `summarizeResource` AllergyIntolerance handler — preserved verbatim) |
| DiagnosticReport | (per `summarizeResource` DiagnosticReport handler — preserved verbatim) |

### Surfaces that emit NO new copy in Phase 51

| Element | Copy |
|---------|------|
| Primary CTA | NOT APPLICABLE — Phase 51 introduces no new button, no new modal, no new alert |
| Empty state heading | NOT APPLICABLE — no new empty state surface; `IncomingReferencesPanel` returns `null` (existing behavior) for resources with no catalog entry |
| Empty state body | NOT APPLICABLE |
| Error state | NOT APPLICABLE — Phase 51 introduces no new error path; existing per-fetch silent-fallback behavior preserved verbatim |
| Destructive confirmation | NOT APPLICABLE — no destructive action |
| Tooltip on graph node | UNCHANGED — `summarizeResource(target).secondary` (inherited from Phase 49) |
| Toolbar / depth-slider / page-heading copy | UNCHANGED — Phase 51 does NOT modify `ResourceGraphView.tsx` |

### Copy invariants for Phase 51

- **No new strings** are added to any source file in Phase 51.
- **No existing user-facing string** in any modified file is changed (the Encounter
  field-priority shift is a *content selection* shift, not a string-table edit).
- **No console.log / console.warn / console.error additions** — no new diagnostic

- The `IconShareplay` semantic mismatch on `PatientHeaderCard`'s `$everything`

## Interaction Contracts

Phase 51 introduces exactly **one** new interaction contract (GAP-2 fix) and **one**
companion href-shape contract (orchestrator addendum). Everything else is preserved
verbatim from prior phases.

### GAP-2 — Graph node click preserves patient context

| Surface | Trigger | Pre-Phase-51 behavior | Post-Phase-51 behavior |
|---------|---------|------------------------|-------------------------|
| `<ResourceGraphNode>` clicked from `/patients/:patientId/:type/:id/graph` | Single click on Card | `navigate('/explorer/:targetType/:targetId')` — patient context **dropped**, user lands in generic Explorer | `navigate('/patients/:patientId/:targetType/:targetId')` — patient context **preserved**, user stays inside Patient browser |
| `<ResourceGraphNode>` clicked from `/explorer/:type/:id/graph` | Single click on Card | `navigate('/explorer/:targetType/:targetId')` (no `patientId` in route params) | `navigate('/explorer/:targetType/:targetId')` — **unchanged** (fallback branch) |
| `<ResourceGraphNode>` keyboard activation | Enter / Space (Mantine `Card` is not natively keyboard-focusable; existing behavior preserved — no new keyboard handling introduced in Phase 51) | (existing) | (unchanged) |
| `<ResourceGraphNode>` hover | Mouse hover | Mantine `<Tooltip>` shows `summarizeResource(target).secondary` | **UNCHANGED** — same Tooltip, same content, same position (`right`), same `withArrow` |

### Orchestrator addendum — Reference card click preserves patient context

| Surface | Trigger | Pre-Phase-51 behavior | Post-Phase-51 behavior |
|---------|---------|------------------------|-------------------------|
| `<RelatedResourcesPanel>` card clicked from a patient-scoped detail page (`/patients/:patientId/…`) | Single click on card | `navigate('/explorer/:type?{param}={ref}')` — patient context **dropped** | `navigate('/patients/:patientId/:type?{param}={ref}')` — patient context **preserved** |
| `<RelatedResourcesPanel>` card clicked from a generic Explorer detail page (`/explorer/:type/:id`) | Single click on card | `navigate('/explorer/:type?{param}={ref}')` | **UNCHANGED** — same href shape (no `patientId` in route params) |
| Visual chrome of the card grid | — | (existing) | **UNCHANGED** — same `<Paper>`, same icons, same counts, same hover state, same loading/empty/error semantics |

### Browser back / forward

`navigate(…)` calls in Phase 51 changes use react-router's standard `navigate(href)`
(no `replace: true`, no `state:`). Browser history is therefore **pushed** for every
node-click and card-click — back returns to the graph view (or detail page) the user
came from. This matches the inherited Phase 49 D-16 contract.

### Theme switch

Phase 51 does NOT touch `useMantineColorScheme`, `setColorScheme`, or `graph.module.css`.
The Phase 49 D-11 theme bridge is preserved verbatim. Theme switching from light → dark
on the graph view continues to work without remount (verified by Phase 49 D-20.4 test;
Phase 51 must not break this test).
