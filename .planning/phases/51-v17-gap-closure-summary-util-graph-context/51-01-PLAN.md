Encounter handler (canonical field-priority — line 217-224 of summarizeResource.ts):
```typescript
function summarizeEncounter(e: Encounter): Summary {
  // class.display → type[0] (via getCodeDisplay) → '' (no fallback to "Encounter")
  const primary = e.class?.display ?? getCodeDisplay(e.type?.[0]);
  return {
    primary,
    secondary: e.period?.start?.slice(0, 10),
  };
}
```

Condition handler (line 210-215):
```typescript
function summarizeCondition(c: Condition): Summary {
  // primary = getCodeDisplay(code) which walks code.text → code.coding[0].display → code.coding[0].code
  return {
    primary: getCodeDisplay(c.code),
    secondary: c.onsetDateTime?.slice(0, 10),
  };
}
```

Procedure handler (line 240-245):
```typescript
function summarizeProcedure(p: Procedure): Summary {
  return {
    primary: getCodeDisplay(p.code),
    secondary: p.performedDateTime?.slice(0, 10),
  };
}
```

Observation handler (line 175-208) — note: emits `<value> <unit> · <code>` for lab observations (category=laboratory) and bare `code` for non-lab. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| FHIR server → Medplum client → component | Timeline fetches `Encounter`/`Condition`/`Procedure`/`Observation`/`MedicationStatement`/etc. for the current `patientId` via `client.searchResources` / `client.get(client.fhirUrl(...))`. Resource bodies are untrusted (server may return malformed CodeableConcept, missing `class.display`, prototype-pollution attempts via JSON keys). |
| Component → render tree | Summary strings flow into `<Text>` / `<Tooltip>` children and into `<UnstyledButton>` icon labels. React auto-escapes string children — no dangerouslySetInnerHTML. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-01-01 | Tampering (T) | `summarizeResource` consuming server-returned `Resource` | accept | `summarizeResource` is pure (no eval, no Function, no spread of attacker data) and uses `toRecord` (the Phase 22 CHRT-06 sanctioned pattern: bracket reads only, no prototype merge). The function is read-only and renders escaped strings. No new attack surface introduced by this plan. |
| T-51-01-02 | Information Disclosure (I) | Encounter `class.display` rendered in Tooltip | accept | The post-refactor field-priority change can surface a different sub-field of the Encounter (`class.display` vs. `type[0].text`); both fields come from the same authenticated FHIR server and are already exposed elsewhere in the UI (Encounter detail page, `summarizeResource` Explorer column). No PII boundary crossed. |
| T-51-01-03 | Denial of Service (D) | `summarizeResource` walker on a malformed deep-nested resource | accept | The generic walker (lines 281-328 of `summarizeResource.ts`) reads at most 7 fields with bracketed access — O(1) per resource. No recursion. No regex backtracking (the only regex is `/^[A-Za-z0-9]+$/` in `isShortAlphanumeric`, linear). PatientTimeline already iterates `bundle.entry ?? []` per resource type with a hard `_count=200` cap (line 122). No amplification introduced. |
| T-51-01-04 | Repudiation (R) | None — read-only summary | accept | No state change; no audit log requirement; no user action attribution affected. |
</threat_model>
