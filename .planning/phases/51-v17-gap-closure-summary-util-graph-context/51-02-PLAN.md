<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL bar / location.pathname → react-router → useParams | Route params (`patientId`, `resourceType`, `id`) come from the URL, which is **untrusted user input**. An attacker can craft a URL like `/patients/..%2Fetc%2Fpasswd/Patient/p1/graph` to attempt path traversal or to inject special characters into a downstream `navigate()` call. |
| ResourceGraphNode → useNavigate → react-router | `navigate(path)` accepts a string template; if `patientId` contains `/`, `?`, `#`, or other path-meaningful characters, the resulting URL would split into unintended segments or expose query/hash injection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-02-01 | Tampering (T) — path injection via patientId | `safeNavigate` | mitigate | Apply `FHIR_ID_PATTERN.test(patientId)` BEFORE incorporating `patientId` into the navigate target. The regex `/^[A-Za-z0-9][A-Za-z0-9\-.]{0,63}$/` rejects `/`, `?`, `#`, `..`, whitespace, and any character outside the FHIR-id charset. This is the same validator already applied to the target `id` (line 26) and `type` (line 25 — `FHIR_REFERENCE_PATTERN`). The new test "FHIR_ID_PATTERN rejects malformed patientId" exercises this branch. |
| T-51-02-02 | Information Disclosure (I) — patient context leak via referer | `navigate(/patients/${patientId}/...)` | accept | The patient-scoped path is already reachable directly via the route registered in App.tsx:151+157. No new exposure surface; the URL only encodes data already authenticated for the session. The Referer header for inter-app navigation (target: same origin) is governed by the platform's existing referrer policy. |
| T-51-02-03 | Elevation of Privilege (E) — bypass via crafted patientId | `safeNavigate` | mitigate | The validator above also blocks attempts to escalate by setting `patientId` to something like `'p1/../admin'` which would otherwise traverse segments. `FHIR_ID_PATTERN` rejects `/` so the attack surface is closed. Plan-level test asserts the fallback fires. |
| T-51-02-04 | Denial of Service (D) | `safeNavigate` | accept | `safeNavigate` is O(1), no recursion, no async work. Click handlers can't be amplified via DOM mutation observers because the patch keeps the click target a single Mantine `<Card>` (no synthetic events). |
| T-51-02-05 | Repudiation (R) | None — read-only navigation | accept | No state mutation, no audit log requirement. |
</threat_model>
