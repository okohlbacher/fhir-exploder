# Quick 260423-gz9: Date range picker UX

## Task

CohortBuilderForm's `DatePickerInput type="range"` requires clicking month-by-month
to reach multi-year ranges. For clinical use cases like "patients born before
1960" or "observations in 2001-2025" this is very tedious.

Two requests from Phase 23 UAT:
1. Clicking the month/year header should cascade to a year/decade grid.
2. Users should be able to type a range directly (e.g. `2001-2025`).

## Implementation

Mantine 8 `DatePickerInput` exposes `maxLevel: 'month' | 'year' | 'decade'` — this
controls how far up the header-click cascade can go. Setting `maxLevel="decade"`
enables month → year → decade click-cascade on the header.

For typed ranges, add a plain `TextInput` **above** the DatePickerInput that
accepts these formats (whitespace-tolerant, `-` or `–` or `to` as separators):

| Input | Interpreted as |
|-------|---------------|
| `2001` | 2001-01-01 → 2001-12-31 |
| `2001-2025` | 2001-01-01 → 2025-12-31 |
| `2024-03 - 2026-04` | 2024-03-01 → 2026-04-30 |
| `2024-03-15 to 2026-04-20` | literal |

Parser lives inline in the component (small, no new module). On valid parse,
sets the DatePickerInput value via the existing `setDateRange` state setter.
Invalid input does not clobber the picker state (shows an inline error).

## Non-goals

- Parsing every possible ISO variant, localized month names, or relative ranges
  ("last 6 months"). Clinical UAT examples are the target.
- Replacing the calendar — it stays as the primary control; typed input is a
  shortcut.
- Touching any other date pickers in the app.

## Verification

- `npm run build` exits 0.
- `npm test` exits 0.
- Manual: opening the calendar, clicking the "March 2026" header once jumps to
  year view; clicking again jumps to decade view. Typing `2001-2025` in the new
  text input and pressing Enter sets the picker to 2001-01-01 – 2025-12-31.
