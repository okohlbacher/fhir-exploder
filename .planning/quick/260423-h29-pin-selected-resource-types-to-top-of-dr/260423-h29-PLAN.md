# Quick 260423-h29: Pin selected resource types to top of MultiSelect

## Task

The `Resource types` MultiSelect on the /quality toolbar lists all resource
types from the server in default order. With a large Blaze instance the list
is long, making it hard to see which types are currently selected. Users
expect selected items to appear at the top of the dropdown.

Note: the source todo references `QualityDashboard.tsx` which doesn't exist
anymore — the actual component is `src/components/quality/ResourceTypeSelector.tsx`
(renamed in Phase 21-04). Todo stays accurate in intent.

## Implementation

Inside `ResourceTypeSelector`, derive a sorted `data` array with `useMemo`:
selected items first (in selection order), then the remaining types in their
original order. Pass the sorted array to `MultiSelect`'s `data` prop.

```ts
const sortedData = useMemo(() => {
  const selectedSet = new Set(value);
  const selected = value.filter((v) => types.includes(v));
  const rest = types.filter((t) => !selectedSet.has(t));
  return [...selected, ...rest];
}, [types, value]);
```

Edge cases handled:
- `value` contains a type not in `types` (stale selection) — filtered out so
  the dropdown only shows types from `types`.
- Duplicate protection — `Set` dedup on the selected check.

## Non-goals

- Changing search/filter behavior (Mantine's `searchable` still works across
  the full list).
- Animating the reorder. The list may shuffle while open — acceptable for v1;
  if it's distracting we can gate sorting on `onDropdownOpen`.
- Refactoring the component API.
