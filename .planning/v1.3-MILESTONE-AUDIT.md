### Phase 22 — Code Review Warnings (3 items)

Captured in [22-REVIEW.md](phases/22-programmatic-cohort-definition-fhirpath-fdpg/22-REVIEW.md):

- **WR-01** — `handleExport` closure in `CohortsPage.tsx`: per-row Export menu item serializes the currently-iterated cohort, but loop variable capture means clicking Export on a non-current row may serialize the wrong cohort.
- **WR-02** — `activateCohort` in `useCohorts.ts` bypasses the `persist` quota-probe branch that `addCohort`/`updateCohort` use; a full-quota localStorage could silently drop the active-cohort write.
- **WR-03** — `PATIENT_REF_CAP = 10_000` truncation warning in `parsePatientRefs` can false-positive when users paste near-cap lists — the warning fires before dedupe, so 10_050 non-unique IDs that dedupe to 9_900 would still show "Cohort truncated" copy.

### Integration Notes (non-blocking)

- `FhirpathLike` redundancy in `fdpgCodec.ts:51-52` — the merged `CohortCriterion` union makes the alias inert. Safe to inline.
- `EditCohortModal` "Cohort updated" toast reads the pre-save cohort name; if the user renames in the same Save action the toast shows stale text. Cosmetic.
