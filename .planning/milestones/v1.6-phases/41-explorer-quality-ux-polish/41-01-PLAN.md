<objective>
Replace the existing ad-hoc "Show/Hide empty" Button + `useState(false)` toggle in
ResourceTypeLanding.tsx with a Mantine `<Switch>` labeled "Hide empty resource types"
that persists across page reloads under localStorage key
`explorer.hideEmptyResourceTypes.v1`.

Default OFF means empty types are SHOWN by default. **This flips v1.5's existing
default**: the legacy code defaulted to hide-empty (state `showEmpty: false`,
filter applied), with a "Show empty" button to reveal them. The new EXPL-01
default-off Switch means zero-count types render unconditionally on first load —
giving the user full visibility — and toggling the Switch ON filters them out.
Existing users who depended on hide-empty-by-default will see a one-time change
and need to flip the Switch ON; the localStorage persistence then keeps it on
across reloads.

When the Switch is ON, types with `counts[type] === 0` collapse out of the
per-category groupings; loading rows always render so users never lose
visibility into still-counting types. The legacy "Show empty" Button + `useState`
are REPLACED entirely by the Switch + `useLocalStorage` — no coexistence.

Purpose: Closes backlog Phase 999.1 (promoted to EXPL-01 in Phase 41 per
ROADMAP.md). Verifier observation during Phase 38 HUMAN-UAT: the explorer landing
shows ~5 zero-count types stacked in noisy categories on a typical Synthea bundle
(`AllergyIntolerance`, `Consent`, `Immunization`, `ServiceRequest`,
`MedicationStatement`).

Output: Updated ResourceTypeLanding.tsx + new colocated regression test.
</objective>
