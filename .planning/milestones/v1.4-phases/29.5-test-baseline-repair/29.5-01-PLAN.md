# Plan 29.5-01: Test Baseline Repair

## Objective

Repair the 22 pre-existing test failures on `main` so phase 30 (layout redesign) can
enforce `npm test exits 0` as a per-step gate. This is a **test-setup-only** repair —
no production code changes.

## Root Causes Diagnosed

1. **Missing `SettingsProvider` wrapper** (affects 21 of 22 failing tests across 7
   files). These tests render components (`Sidebar`, `PatientListPage`,
   `PatientDetailPage`, `QualityOverviewPage`, `ResourceTypeLanding`,
   `HumanReadableView`, `FhirResourcesView`) that transitively render
   `FhirSettingsModal` / `TerminologySettingsModal` / other consumers of
   `useSettings()`. `useSettingsContext()` throws
   `"useSettingsContext must be used within SettingsProvider"` when no provider is
   present in the render tree.

2. **Mock `MedplumClient` missing `fhirUrl()`** (affects 1 unit test:
   `probeTerminologyHealth returns 'ok' when the metadata endpoint resolves`).
   `probe.ts` calls `client.fhirUrl('metadata').toString()`; the
   `mockMedplumClientForTerminology` fixture only mocks `get`, so
   `client.fhirUrl(...)` is `undefined` and `.toString()` throws. The catch clause
   then returns `'unreachable'` instead of `'ok'`.

## Approach

Minimal, surgical, single commit:

1. Add `fhirUrl` to `mockMedplumClientForTerminology` — return a plain object whose
   `toString()` yields the requested path (e.g. `'metadata'`), so the existing mock
   `get()` still matches `path === 'metadata'`.

2. Introduce a shared `renderWithProviders` helper (or inline a minimal
   `<SettingsProvider>` wrapper) in each failing React test file. Do **not** refactor
   tests beyond what's needed — keep each file's existing structure.

3. Run `npm test` until green. Confirm `npm run build` still passes.

## Tasks

### Task 1 — Fix terminology fixture

- Edit `src/__tests__/fixtures/terminology.ts`: extend the returned object with
  `fhirUrl: (path: string) => ({ toString: () => path })`.
- Run `npm test -- terminology-health` to confirm 4/4 pass.

### Task 2 — Wrap each React test with SettingsProvider

For each of the 7 failing test files, add a wrapper inside the existing
`renderXxx()` / `render()` call:

```tsx
import { SettingsProvider } from '../contexts/SettingsContext';
// ...
render(
  <MemoryRouter>
    <MantineProvider>
      <SettingsProvider>
        {/* existing tree */}
      </SettingsProvider>
    </MantineProvider>
  </MemoryRouter>,
);
```
