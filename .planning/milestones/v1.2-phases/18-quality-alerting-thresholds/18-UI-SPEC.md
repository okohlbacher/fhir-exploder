# Phase 18 — UI Design Contract

> Visual and interaction contract for the Quality Alerting & Thresholds phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 18 adds per-metric quality thresholds (localStorage persistence) and flags metric breaches visually on the quality dashboard. Two UI surfaces are touched:

1. **`/quality/thresholds`** — a NEW dedicated configuration page (D-04): Mantine Table, one row per metric × numeric threshold input × default badge × clear button, plus a page-level "Reset to defaults" action.
2. **`OverviewStrip` on `/quality`** — expanded from 4 summary cards to 9 tiles (7 metrics + Total resources + Resource types). Each metric tile shows label, % clean value, RingProgress arc, and — when breached — a `threshold: X%` annotation below the score. Breached tiles render their ring + numeric value in red. Tiles are clickable and navigate to the corresponding quality tab.

All breach signals are **visual-only**: no toasts, no sounds, no tab-header badges, no banners (D-13, D-19). No new dependencies, no new design tokens, no theme changes. The phase reuses Mantine 8 primitives already in the codebase (`Table`, `NumberInput`, `RingProgress`, `Card`, `Badge`, `ActionIcon`, `Modal`, `Button`) plus existing `@mantine/hooks` `useLocalStorage`.

## Color

Inherits Mantine default light theme from prior phases. No new colors introduced. The 60/30/10 split is unchanged.

| Role | Value | Mantine Token | Usage |
|------|-------|---------------|-------|
| Dominant (60%) | `#FFFFFF` | `white` | Page background, tile surfaces, table surface |
| Secondary (30%) | `#F8F9FA` | `gray.0` | Table header row (via Mantine default); subtle badges (`variant="light"`) |
| Accent (10%) | `#228BE6` | `blue.6` | See reserved-for list below |
| Destructive / Breach | `#FA5252` | `red.6` | Breached RingProgress arc + breached numeric value; "Clear" ActionIcon icon when hovered; "Reset to defaults" confirmation Button |

**Accent (blue.6) reserved for:**
- "Configure thresholds" toolbar button on `/quality` (`variant="light"`, `color="blue"` — matches existing "Recompute metrics" button)
- RingProgress arc on OverviewStrip tiles when NOT breached (unchanged default from current code)
- Back link on ThresholdsPage ("Back to Data Quality")
- Focus ring on clickable metric tiles (Mantine's default focus outline)

**Accent is NOT applied to:** table row hover background (use `gray.0`), NumberInput focus border (use Mantine default which is `primaryColor` already), Save/confirm buttons in the Reset confirmation dialog (confirm button is red because it is destructive).

**Red (red.6) — breach signal — reserved for:**
- RingProgress arc `sections[0].color` when metric value < active threshold
- Numeric value `c="red.6"` (Mantine Text `c` prop) when metric value < active threshold
- "Reset to defaults" confirm button (destructive; `color="red"`)
- Trash icon on per-row "Clear" ActionIcon (`color="red"` on hover only; gray at rest)

**Severity-graded gradient (orange → red based on breach depth) is DEFERRED** per CONTEXT D-17 deferred list. Phase 18 ships binary breached / not-breached. A future phase may graduate.

**No-data & not-run states** render NO red signal. Tiles render a gray ring (`sections=[{value: 0, color: 'gray.3'}]`) + em-dash value (`—`) + no threshold annotation. See State Matrix below.

## Interaction Contracts

### I-01: "Configure thresholds" Entry Point

**Trigger:** User is on `/quality`.

**Behavior:**
1. Toolbar's right-hand Group gets a new Button labeled **"Configure thresholds"** (`variant="light"`, `leftSection={<IconAdjustmentsAlt size={16} />}`), placed to the LEFT of the existing "Recompute metrics" button.
2. Clicking navigates to `/quality/thresholds` (React Router `navigate('/quality/thresholds')`).
3. Browser back returns to `/quality` with tab + cohort + sample-size state intact (route-level state is preserved by React Router; the quality page uses `keepMounted` on tabs).
4. Keyboard: `Tab` reaches the button; `Enter` / `Space` activates.

**Button copy:** `Configure thresholds` (matches D-04 exactly).

### I-02: ThresholdsPage Layout & Interactions

**Trigger:** User navigates to `/quality/thresholds`.

**Default state:** Page renders immediately. Uses `useThresholds()` to read current stored overrides merged over `DEFAULT_THRESHOLDS`. No network calls; purely local state.

**Layout:**
1. `<Stack gap="lg" p="xl">`:
   - Row 1: Back link `<Anchor component={Link} to="/quality">← Back to Data Quality</Anchor>` (inherits blue.6 accent).
   - Row 2: `<Title order={2}>Configure Quality Thresholds</Title>`.
   - Row 3: `<Text size="sm" c="dimmed">Set the minimum acceptable score for each quality metric. Metrics below their threshold are flagged in red on the dashboard. Leave a row empty to disable alerting for that metric.</Text>`.
   - Row 4: `<Paper withBorder radius="sm" p="md">` containing the ThresholdsTable.
   - Row 5: `<Group justify="flex-end">` containing a single `<Button variant="subtle" color="red" leftSection={<IconRestore size={16} />}>Reset to defaults</Button>`.

**Table:** Mantine `<Table striped withTableBorder withColumnBorders={false}>`.

| Column | Header | Width | Content |
|--------|--------|-------|---------|
| Metric | `Metric` | auto | Metric label (e.g., "Completeness"). Left-aligned. `fw={600}`. |
| Default | `Default` | 120px | `{DEFAULT_THRESHOLDS[key]}%` in plain text. |
| Threshold | `Alert if below` | 200px | Mantine `NumberInput` with `min={0}` `max={100}` `step={1}` `suffix="%"`, `value={stored[key] ?? DEFAULT_THRESHOLDS[key]}`, `placeholder="no alert"`. |
| Active | `Active` | 100px | If `stored[key] !== undefined` AND `stored[key] !== null` → `<Badge color="blue" variant="light" size="sm">custom</Badge>`. Else if `stored[key] === null` → `<Badge color="gray" variant="light" size="sm">disabled</Badge>`. Else → `<Badge color="gray" variant="outline" size="sm">default</Badge>`. |
| Actions | (empty) | 60px | `<ActionIcon variant="subtle" color="gray" aria-label="Clear threshold for {label}">`<IconX size={14} />`</ActionIcon>`. Hover state: `color="red"`. Clicking sets the key to `null` in stored object (disables alerting for that metric); if metric is already at default, the icon is disabled. |

**NumberInput save semantics (D-06):**
- Save on blur (not on every keystroke) — avoids localStorage thrash.
- Invalid input (> 100, < 0, non-numeric) → Mantine's built-in `clampBehavior="strict"` enforces range; non-numeric characters are filtered by NumberInput already.
- Empty input on blur → treat as "unset" (remove key from stored object → falls back to default). Active column reverts to `default` badge.
- Enter key triggers blur (Mantine NumberInput default).
- No dedicated Save button. No "unsaved changes" banner.

**Per-row Clear button:**
- Sets `stored[key] = null` (explicit disable, distinct from absent key which means "use default"). Active badge switches to `disabled`. NumberInput becomes empty.
- Only one state is reachable from the UI: clicking the ActionIcon disables alerting. To reset to default (remove the override), the user either types the default value back in and blurs, or uses the page-level "Reset to defaults".

**Rationale for null vs undefined distinction:** Storing `null` is how the user signals "I intentionally turned this off" (versus "I haven't touched this"). This matters if `DEFAULT_THRESHOLDS` is later tuned in a future release — disabled metrics stay disabled; untouched metrics pick up the new default. Planner must honor this in the hook contract.

### I-03: Reset to Defaults Confirmation

**Trigger:** User clicks "Reset to defaults" on ThresholdsPage.

**Behavior:**
1. Mantine `Modal` opens (`centered`, `size="md"`, `radius="sm"`).
2. Modal title: **"Reset thresholds to defaults?"**
3. Modal body: `<Text size="sm">This will clear all custom thresholds and restore every metric to its shipped default. This cannot be undone from the UI — you will need to re-enter any custom values.</Text>`
4. Modal footer: `<Group justify="flex-end" gap="sm">` with:
   - `<Button variant="default" onClick={close}>Keep current thresholds</Button>`
   - `<Button color="red" onClick={confirm}>Reset to defaults</Button>`
5. Confirm action: writes `{}` to `quality.thresholds.v1` (empty overrides object). Modal closes. Page re-renders — all NumberInputs show `DEFAULT_THRESHOLDS[key]`, all Active badges return to `default`.
6. Notification: `notifications.show({ color: 'blue', title: 'Thresholds reset', message: 'All metrics restored to shipped defaults.' })`.
7. Keyboard: `Esc` closes the modal (dismiss semantics, same as "Keep current thresholds"). `Enter` focuses the destructive button but does NOT auto-submit.

### I-04: Breach Visual Treatment on OverviewStrip

**Trigger:** Quality metrics have populated. For any metric `m`: `isBreached(m, value, threshold)` is true iff `value != null && threshold != null && value < threshold`.

**Behavior:**
1. **Ok state** (value ≥ threshold, or no active threshold): RingProgress `sections=[{value, color: 'blue.6'}]`. Numeric value rendered in default Text color (black / gray.9). No threshold annotation.
2. **Breached state**: RingProgress `sections=[{value, color: 'red.6'}]`. Numeric value rendered in `c="red.6"` `fw={600}`. Subtitle line appears directly below the value: `<Text size="xs" c="dimmed">threshold: {threshold}%</Text>`.
3. **No-data state** (`value === 0` for an issue-count metric AND `sampledResources === 0`, per D-17): RingProgress `sections=[{value: 0, color: 'gray.3'}]`. Numeric value rendered as `—` (em-dash) in `c="dimmed"`. No threshold annotation. `aria-label="{label}: no data"`.
4. **Not-run state** (D-18, metric not yet computed in this session): same as no-data — gray ring, em-dash, no annotation, `aria-label="{label}: not yet run"`.
5. Transitions (ok ↔ breached) are NOT animated — Mantine default color change. Avoids drawing undue attention on every recompute.

**State Matrix:**

| State | Ring color | Ring value | Number color | Number text | Annotation | Click enabled |
|-------|-----------|-----------|-------------|------------|------------|---------------|
| Ok (value present, threshold set, value >= threshold) | `blue.6` | `value` | `gray.9` | `{value}%` | none | yes |
| Ok (value present, no threshold active) | `blue.6` | `value` | `gray.9` | `{value}%` | none | yes |
| Breached | `red.6` | `value` | `red.6` | `{value}%` | `threshold: {N}%` | yes |
| No-data (sampledResources 0) | `gray.3` | `0` | `dimmed` | `—` | none | yes (still navigates) |
| Not-run (not computed this session) | `gray.3` | `0` | `dimmed` | `—` | none | yes |

**No-data vs not-run distinction** is not user-visible — both render identically. The engineering distinction matters for downstream consumers (e.g., the auditor later) but is not a UX affordance in Phase 18.

### I-05: Metric Tile Click-Through

**Trigger:** User clicks anywhere on a metric tile in `OverviewStrip`.

**Behavior:**
1. Entire tile is clickable (not just the label) — `Card component="button"` wraps the whole surface.
2. Click navigates to the corresponding quality tab. Mechanism (planner's choice):
   - Preferred: `navigate('/quality?tab=completeness')` + `QualityOverviewPage` reads `searchParams.get('tab')` and sets `defaultValue` (or `value` / `onChange`) on `<Tabs>`.
   - Acceptable fallback: `navigate('/quality', { state: { activeTab: 'completeness' } })` with `useLocation().state` read in `QualityOverviewPage`.
3. The two informational tiles ("Total resources", "Resource types") are NOT clickable — they remain plain `Card` (not `component="button"`), no hover elevation, no focus outline. Semantically they are read-only status.
4. Metric-tile hover state: Card gains a 1px shadow (`shadow="xs"` on hover via CSS) and cursor becomes `pointer`.
5. Metric-tile focus state: Mantine's default focus-visible outline (2px blue.6) wraps the Card.
6. Keyboard: `Tab` reaches each clickable tile in left-to-right, top-to-bottom order; `Enter` / `Space` activates. Skip order: Total resources and Resource types are NOT in the tab order (they are not buttons).
7. Tile `aria-label` follows pattern: `"{label}: {value}{, breached, threshold: {N}%}. Click to open {tabName} tab."` Example: `"Completeness: 72%, breached, threshold: 80%. Click to open Completeness tab."`

**Tab-key routing map** (`METRIC_ROUTES` in `src/quality/thresholds.ts`):

| Metric key | Tab value |
|-----------|-----------|
| `completeness` | `completeness` |
| `coverage` | `coverage` |
| `validation` | `validation` |
| `plausibility` | `plausibility` |
| `labRanges` | `lab-ranges` |
| `duplicates` | `duplicates` |
| `references` | `references` |

## Empty & Error States

### Empty State: Metric Not Yet Run

**When:** A metric's score has not been computed in this session (e.g., the user has not clicked into the Validation tab yet, so `overallValidation === undefined`).

**Render:** See State Matrix row "Not-run". Gray ring, em-dash, no annotation. No Alert. No banner. The empty state IS the tile.

### Empty State: No Data to Score

**When:** `sampledResources === 0` for an issue-count metric (e.g., no lab Observations present on the server). Per D-17, this is NOT a breach.

**Render:** Same as "Not yet run" (gray ring, em-dash). Visually indistinguishable — the distinction is not surfaced to users.

### Empty State: ThresholdsPage is Never Empty

The thresholds table always renders 7 rows (one per metric). There is no zero-state for the configuration page. If `localStorage` is clear, every row shows its `default` badge and the shipped default value in the NumberInput.

### Error State: localStorage Write Failure

**When:** `setLocalStorage` throws (private browsing mode, storage quota exceeded, etc.).

**Render:** Mantine `notifications.show({ color: 'red', title: 'Could not save threshold', message: 'Your browser blocked writing to local storage. Changes will be lost when you reload.' })`. Does NOT prevent the in-memory state from updating — the NumberInput still reflects the typed value so the user sees that their input was accepted, just not persisted.

### Error State: Invalid localStorage Data

**When:** `quality.thresholds.v1` exists but is not a valid Thresholds shape (corrupted).

**Render:** Silently fall back to `DEFAULT_THRESHOLDS` (treat as empty overrides). Do NOT alert the user — the config page still renders correctly, and the invalid data will be overwritten on next save. Log a `console.warn` for developers.

### Loading State

None needed. All operations are synchronous localStorage reads / writes plus in-memory React state. No network, no async.

## Accessibility Contract

### Thresholds Page

- `<Title order={2}>` establishes page heading; screen readers announce "Configure Quality Thresholds, heading level 2".
- Back link is a proper `<Anchor component={Link}>` — screen readers announce "Back to Data Quality, link".
- Table uses Mantine `<Table>` which renders semantic `<table>` / `<thead>` / `<tbody>` — screen readers announce row/column position.
- Each NumberInput has an implicit label via the table row's first cell (the metric name). Additionally, Mantine's NumberInput accepts `aria-label` — planner should set `aria-label="{metric} threshold"` for redundancy.
- Each Clear ActionIcon has explicit `aria-label="Clear threshold for {label}"`.
- Reset button uses standard `<Button>` — screen readers announce "Reset to defaults, button". Modal that opens is announced as dialog.
- Modal traps focus (Mantine default). `Esc` closes. Focus returns to the Reset button on close.
- Keyboard tab order: Back link → Metric row 1 NumberInput → Metric row 1 Clear → Metric row 2 NumberInput → ... → Reset button.
- All text contrast meets WCAG AA in both light and dark modes (Mantine default palette is pre-validated).

### OverviewStrip

- Informational tiles (Total, Types): rendered as `<div>` / `<Card>`, not focusable, read as static content.
- Metric tiles: rendered as `<button type="button">` (via `Card component="button"`), focusable, reachable via `Tab`, activated via `Enter` / `Space`.
- Breached tiles convey their state via:
  - Color (red) — primary signal for sighted users.
  - Text content ("threshold: 80%") — readable by screen readers.
  - `aria-label` on the button — explicit state announcement: `"Completeness: 72%, breached, threshold: 80%. Click to open Completeness tab."`
  - Focus ring (blue.6 2px outline, Mantine default) — visible keyboard affordance.
- Red-only-as-signal test: a user with red-green colorblindness will still perceive the breach because (a) the numeric value is textually annotated with `threshold: X%`, and (b) the `aria-label` conveys "breached". Color is not the sole signal.
- `aria-live` is NOT applied to the OverviewStrip. Breach state changes happen during user-initiated recomputes; announcing every tile change on recompute would be noisy. Users who re-run and want to hear the outcome can Tab through the tiles post-compute.

### Screen Reader Announcement for Breach Toggle

When a tile transitions ok → breached (e.g., user tightens the threshold on /quality/thresholds and returns to /quality), the announcement happens naturally when the user Tabs to the tile — no explicit `aria-live` region is needed. This is consistent with the "visual-only, no notification layer" constraint of D-13 and D-19.
