## Overview

FHIR Exploder v1.0 delivered a local-first React application for exploring Blaze FHIR server data. Ships with five feature capabilities: Blaze connectivity with settings/capability discovery, generic resource browsing with search/pagination/three display modes, patient-centric views with MII Kerndatensatz module navigation, terminology resolution against the MII Terminology Server with caching and graceful fallback, and a data quality dashboard with counts/completeness/coding-coverage/profile-validation panels. Built on React 18 + Vite + TypeScript + Medplum React + Mantine 8.

## Milestone Summary

### Key Decisions

- **Stack lock:** Medplum React + Mantine 8 + Vite 8 + TypeScript 5.7 + React 18 + react-router v7. No Tailwind, no Next.js, no react-query, no SMART on FHIR — local-first browser-only design.
- **Blaze $validate reality:** F-01 research finding confirmed Blaze does NOT implement $validate on resources. Phase 5 shipped a dual-source design: offline structural walker (bundled MII StructureDefinitions) + optional remote validator via `settings.validation.validatorUrl`.
- **Sampling over full scans:** D-06 locked in Phase 5 — completeness/coverage/validation operate on the first N resources per type (default 100, clamped 10..1000 client-side) to avoid OOMing the browser on 50K+ resource types.
- **Mantine-only visuals for v1:** Deferred `@mantine/charts` + `recharts` install to v2 (saves ~150KB gz). Progress/RingProgress/stacked Progress satisfy D-04 "visual indicator" branch.
- **QualityMetricsContext as rendezvous:** Phase 5 revision pass added a lightweight Context provider so per-type rollups from Completeness (Plan 03) + Coverage (Plan 04) hooks flow back to OverviewStrip cards 3+4 without em-dash placeholders.
- **Patient-aware breadcrumb basePath:** Phase 6 exposed the `basePath` parameter that `useBreadcrumbTrail` already supported; ResourceDetailPage now honors `/patients/:patientId` when mounted under the patient subtree.

### Issues Resolved

- MC-1 (HIGH integration): ResourceDetailPage hardcoded `/explorer` basePath — resolved Phase 6
