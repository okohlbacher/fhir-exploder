# Phase 22 — UI Design Contract

> Visual and interaction contract for Programmatic Cohort Definition (FHIRPath + FDPG). This phase is a **strict extension of the Phase 21 UI-SPEC** — every spacing token, font size, color, weight, focal-point convention, modal pattern, and notification color is reused verbatim from `21-UI-SPEC.md`. New surfaces (FhirpathCriterionCard, Import/Export buttons, SavedCohortRow inline menu, EditCohortModal, DeleteCohortModal) declare additive contract only. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

## Typography

**Reused verbatim from 21-UI-SPEC.md §Typography.** Phase 22 introduces zero new font sizes, zero new weights, and zero new heading roles.

**Distinct font sizes remain exactly 4 — 12px, 14px, 18px, 30px.** Phase 22 must not break this budget.

| Role | Component / size prop | Mantine px | Weight | New usage in this phase |
|------|----------------------|-----------|--------|-------------------------|
| Section heading | `<Title order={4}>` | 18px | 600 | "FHIRPath query (advanced)" card heading on the 4th builder Paper |
| Body | `<Text size="sm">` | 14px | 400 | All descriptive paragraphs in S1, S5, S6, S7, S8; modal body copy |
| Helper / caption | `<Text size="xs" c="dimmed">` | 12px | 400 | Validate result row text ("Matches N patients"); active-cohort warning sub-text; helper section in `<Collapse>` |
| Input label | Mantine input `label` prop | 14px | 500 | FHIRPath Textarea label |
| Input placeholder | Mantine input `placeholder` prop | 14px | 400 | FHIRPath Textarea placeholder example |
| Button label | `<Button>` children | 14px | 500 | Validate, Import, Export, Edit-modal Discard / Save, Delete-modal Discard / Delete |
| Menu item label | `<Menu.Item>` children | 14px | 400 | Edit / Duplicate / Delete menu items per row (Mantine default) |
| Modal heading (S5, S6) | `<Text fw={600} size="sm">` rendered as first child of modal body (NOT the Mantine `<Modal title>` prop) | 14px | 600 | Edit-cohort modal heading + Delete-cohort modal heading — same in-body heading pattern as Phase 21 §Modal title choice |
| Code (FHIRPath examples in helper) | `<Code>` from `@mantine/core` | inherits 14px (Mantine default monospace) | 400 | Example FHIRPath expressions inside the `<Collapse>` helper section |

**Modal title choice (CRITICAL — preserves Phase 21 4-size budget):** Both `EditCohortModal` and `DeleteCohortModal` MUST use `<Modal title={undefined}>` and render the heading as `<Text fw={600} size="sm" id="…-modal-heading">` as the first child of the modal body, with `aria-labelledby` on the `<Modal>`. Using Mantine's native `title` prop would introduce a 5th distinct font size (16px) and break the Typography budget. This is the same pattern Phase 21 established for the Save-cohort modal at `CohortBuilderForm.tsx:303-316`.

**Monospace exception (S1 Textarea):** The FHIRPath Textarea uses `style={{ fontFamily: 'monospace' }}` per D-08 (locked). Mantine's monospace inherits the system monospace stack — no font import, no theme override. The monospace face does not introduce a new declared font; it is a typeface variant of the same 14px size.

**Line heights:** all inherited from Mantine defaults. No overrides.

**Font weights used:** exactly two — 400 and 500/600 — same as Phase 21. No new weights.

| Success state text — `green` | Mantine `green.7` (text only) | NEW: Validate success result text "Matches N patients" rendered as `<Text size="xs" c="green.7">`. Used as **status text only** (≤1 line per surface), never as a fill, button, or border. |

**Accent reserved for (Phase 22 additions to Phase 21's list):**
1. Validate button (filled blue when idle/ready)
2. Edit-modal Save changes button (filled blue)
3. Success toasts (color: 'blue') for cohort-saved / duplicated / imported / exported events
4. Active-cohort badge (already reserved in Phase 21; Phase 22 does not change this)

**Destructive (red) reserved for:**
1. Delete-modal Delete cohort button (filled red)
2. Delete `Menu.Item` (red text + red trash icon)
3. FDPG import failure Alert
4. All error toasts

**Status-text color clarification (`green.7`):** Phase 21 did not declare green. Phase 22 introduces a single 1-line green status text on the Validate result row to communicate "successful translation + non-empty count" without overloading the blue accent (which is reserved for actionable CTAs). Green is used **as text only**, never as fill, border, badge, button, or icon background. This stays inside the 60/30/10 contract because: blue accent count remains unchanged (no new blue surfaces beyond the buttons listed above); the green is a per-instance result indicator (≤1 line per validation), not a recurring surface. **If the checker rejects this on the 60/30/10 strict reading**, fall back to rendering the success result row as `<Text size="xs">Matches {n} patients</Text>` in the default body color with an `<IconCheck size={14} color="green" />` leftSection — same semantic, even more conservative.

**Borders / shadows:** unchanged — `<Paper withBorder radius="sm" p="md">` for the 4th card; Mantine default modal overlay for S5 + S6.

**File picker UX:** Use Mantine `<FileButton>` from `@mantine/core` wrapping the Import `<Button>`. `<FileButton>` is the established Mantine pattern for triggering a file dialog without a visible `<input>` element; it returns a `File | null` to the onChange handler. Accept attribute: `accept=".json,application/json"`. Hard cap inbound file size at 1 MB (per 22-RESEARCH.md §Security Domain Pattern) — reject larger files with red toast before parsing.

### Single-column scroll vs Tabs decision (page-level)

**Decision: stay with single-column scroll** (Phase 21 layout preserved).

Rationale: After Phase 22 adds the 4th builder card and the toolbar Import button, scroll length on `/quality/cohorts` at 1080p (1920×1080 viewport) is approximately:
- Page chrome (Back link + Title + description): ~120px
- Saved cohorts card (heading + Import + ~3 rows assumed): ~280px
- Builder card heading + description + 3 existing cards (date / condition / refs / Save area): ~720px
- 4th FHIRPath card: ~280px (collapsed helper) / ~500px (expanded helper)

Total: ~1400–1620px → ~1.3–1.5 viewport heights of scroll on 1080p. Acceptable single-page authoring per D-08 ("single-page authoring of a hybrid cohort matches D-07"). Tabs would mask hybrid AND-composition (each tab would feel like a separate criterion type, undermining the "all criteria AND together" mental model).

If scroll becomes problematic in Phase 23, revisit with the option to collapse each criterion card into an accordion (`<Accordion>` from `@mantine/core`) — defer that to a future phase.
